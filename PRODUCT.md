# Rex Rune: product

## Purpose

A native Linux client for [Rex](https://www.superlogical.com/rex) servers, aimed at people who do daily coding work across several machines. It attaches to server-owned sessions that other Rex clients (for example the official Mac and iOS apps) can use at the same time. Closing the client leaves programs running on the server.

## Platform and stack

Native Linux desktop (Wayland and X11). Rust, [Rune](https://github.com/anomalyco/rune) (wgpu/winit, rune-kit) and libghostty-vt.

## Principles

- **Attachment-only by default.** Attaching and reconnecting never start, stop or reconfigure a server. A missing default server on an SSH host may be started once only after a separate preview and explicit confirmation; this never enables future auto-starts. Sessions are never created or destroyed unless asked explicitly.
- **The server owns the terminal.** Terminal content, colours and split geometry come from the server; the client draws chrome around them and never recolours output. The client may declare a terminal theme to the server, as it declares a size: Rex applies it at once when this client owns the terminal or no client does, and otherwise when this client becomes the owner. Rex keeps each client's last declaration for each terminal, and the terminal shows its owner's; an owner that declared nothing leaves the colours as they were. So while this client owns a terminal (or nobody does), other clients viewing it see the declared theme, just as they see its size, and when another client that declared a theme takes it over, everyone sees that one. Because Rex keeps a declaration across launches, following the server's colours is not silence once this client has declared any theme: from then on it declares Rex's own colours (an empty theme) once per terminal per connection to each terminal it owns or nobody owns, so an old theme never comes back unasked. A client that has never declared a theme declares nothing.
- **Hosts → sessions → tabs.** Saved hosts contain sessions; a session's Rex windows are tabs and its splits are the server's. Navigation must stay useful with a dozen or more sessions across several hosts.
- **Compact and calm.** One toolbar, rounded pane cards on a flat dark ground. Popups and highlights animate; terminal content never does.
- **Safe by default.** Closing a pane or tab names what will end and defaults to **Keep running**. A download is never opened, run or made executable by the client, and its question defaults to **Cancel**. Quitting the app cancels running downloads without asking. A transport failure pauses input rather than queueing it.
- **Keyboard first.** Workspace shortcuts are rebindable/removable through Settings or a user-owned file and Rex’s layered keymap. Settings saves a separate app-owned layer in workspace.json, above the user’s file, without rewriting that file. The active host’s effective map drives dispatch, Settings and Commands; offline defaults still work. Ordinary keys retain Rex’s Lua handling through `client.key`.

## Capabilities

Saved hosts, sessions, tabs, authoritative splits, snapshot restoration, live output, input, mouse reporting, reconnect and resume. Terminal search covers the screen and scrollback. API revisions 10, 11, 12 and 13 are supported; older servers are refused rather than carried along while Rex is in alpha. Bootstrap bundles the initial terminal tickets; live streams and data resume take priority over new snapshots. On revision 11 or newer, files dropped on a pane or pasted are uploaded to the terminal's machine and their paths typed into it. On revision 13 or newer, **Download file…** (`pane.download`) saves a file from the terminal's machine into a local folder over the Rex connection, with progress in the toolbar and a Downloads list: it never overwrites a file and never opens or runs one, offers a finished file only **Show in folder** (open it from the file manager), confirms files of 1 GiB or more or too large for the free space, and never retries or resumes. Only a person at this client can start one; `client.perform` cannot. Program activity (OSC 7501) marks tabs and, for tabs out of view, sends desktop notifications. Settings can set up Rex's skill and hooks for coding agents on this machine through the local `rex skill` command, previewing every change. Split panes support Comfortable (rounded cards with headers) and Compact (edge-to-edge with 1 pt separators) density modes and configurable terminal padding (0–32 pt). Pane headers carry Split right, Split down, Zoom and Close buttons for their pane and can be shown with the density (the default), always, on hover or never. Official and Nix builds check signed GitHub release metadata (`latest.json` and `latest.json.minisig`) against embedded Minisign public keys and display non-blocking, channel-specific upgrade guidance. Verified user-writable install.sh installations under `~/.local` can install signed updates in-app and restart when ready; automatic installation is a separate default-off preference. Package-managed and source builds never self-update.

Shortcuts use Linux defaults, each host’s Rex config, user-owned client overrides and app-owned recorded shortcuts, in that order. Settings explains effective sources and problems and records keys in workspace.json without writing the user’s override file. Sequences show their pending prefix and never leak consumed prefixes to programs; only explicit `pane.send_key` bypasses Lua key bindings. Server-side actions execute on their host, from a bound key or from Commands, which lists the ones that need no arguments; each runs once and a failure is reported, never retried. Queued known client actions run once on the UI thread. Requests from another client (`client.perform`) follow per-host Remote control consent, off by default even locally. Only the declared view-only subset can run, on that host, outside panels and after a pause in typing; clipboard, typing, creation, destruction, dialogs and cross-host preference changes remain unavailable. Every performed request names its host, requester and action in an in-app notice.

SSH attachment uses OpenSSH socket forwarding. If SSH succeeds but finds no default server, a separate Start personal server dialog names the target and command, explains the changes and defaults to Not now. Explicit confirmation invokes native Rex SSH auto-start once, then resumes socket forwarding. Setup requires preview.14/API 12 locally and remotely; failures never retry. Installation remains the manual `rex server install ssh://host` alternative: the app never answers installer prompts or installs packages/services.

## Out of scope for now

Complete Kitty graphics, distribution packages, and screen-reader support for the terminal itself. Rune's AT-SPI tree is on and names the chrome, but it has not been tried with a screen reader, and the terminal pane exposes only visible text as plain labels (no caret, selection or focus). See the README's Accessibility section and its list of unvalidated areas.
