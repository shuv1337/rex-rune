# Contributor and agent guide

Rex Linux is a native Linux client for Rex terminal servers, written in Rust on Rune. See [README.md](README.md) for what it does and how to run it, [PRODUCT.md](PRODUCT.md) for product principles and [DESIGN.md](DESIGN.md) for the design system.

## Build and test

```sh
cargo build --locked --release --bin rex-linux          # the app
cargo test --locked --all-features                      # unit and headless UI tests
cargo fmt --all -- --check
cargo clippy --locked --all-targets --all-features -- -D warnings

# Protocol-only binaries (no UI libraries needed):
cargo run --locked --no-default-features --bin rex-probe
cargo run --locked --no-default-features --bin rex-workspace-probe

# Vendored SDK tests:
cargo test --manifest-path vendor/rexrs/Cargo.toml --all-features
```

Requirements are listed in the README (Rust 1.96+, Zig 0.17.x for `ghostty-vt`, Linux graphics and input libraries). `Cargo.lock` is committed; keep `--locked` working.

Some probes connect to the configured Rex server and create sessions there. Of the Python scripts in `scripts/`, `x11-smoke.py`, `rune-acceptance-x11.py` and `wayland-seat-smoke.py` require `REX_SERVER` to name a disposable server and exit without it; the rest start their own. Every script that launches the client honours `REX_BIN`. Run them only against a disposable server or socket you control, and check each script's requirements in its docstring. `rex-download-probe <unix endpoint> <work dir>` creates a session on the server it is given and downloads real files from it; it refuses the default per-user socket path. Scripts that select text by pointer pin `pane_padding` in their private `workspace.json` and compute positions from it (`grid_origin` in `rune-acceptance-x11.py`), so a changed default does not break them. Anything that exercises the UI against real input (`x11-smoke.py`, `rune-acceptance-x11.py`, `wayland-seat-smoke.py`) needs a built binary and the tools it names.

## Code layout

- Protocol and model library (`src/lib.rs`, no UI dependency):
  - `transport.rs`, `wire.rs`: Unix/HTTPS WebSockets, data tickets, snapshot framing.
  - `connection.rs` (and `connection/`): one control connection per host, block-keyed terminal streams, the `Options` CLI definition. `connection/server_info.rs`: the server's version and status on `HostModel::server_info`, read-only and once per connection.
  - `terminal.rs`: Ghostty decoding and render frames. `terminal/search.rs`: searching the screen and scrollback with Ghostty's search. `links.rs`: OSC 8 hyperlinks and text URLs in a frame.
  - `layout.rs`: split placement. `settings.rs`: local configuration. `settings/terminal.rs`: local cursor, selection and sequence-hint preferences, with backwards-compatible defaults. `settings/typography.rs`: compatible font style, line height, spacing and program bold/italic preferences under `terminal.font`; existing top-level font keys stay put.
  - `download.rs` and `download/`: the file download core for API 13 (`name.rs` sanitizes hostile names, `store.rs` the destination folder, partial files and crash records, `stream.rs` the data stream; nothing in it opens or runs a downloaded file); driven by `HostCommand::Download` in `connection/downloads.rs`.
  - `ssh.rs`: `ssh://` endpoints, a Rex socket forwarded with `ssh -L`. `tailnet.rs`: the machines in `tailscale status --json` and the check for a Rex server on each.
- `src/main.rs` and `src/app/`: the Rune front end (behind the default `ui` feature).
  - `workspace.rs`: workspace state and behavior (hosts, sessions, tabs, panes, requests, preferences, notices). Host and terminal workers wake the UI through `rune::AppHandle::update`.
  - `panel.rs`: popup and dialog state and the switcher and pane-menu lists. `commands.rs`: every Commands row in one table, grouped by what it acts on; an action without a row there needs a stated reason, and `command_tests.rs` pins the ids. `discover.rs`: the Add host list of the tailnet's machines.
  - `actions.rs`: the named actions and their `Spec::remote()` decisions. `keycaps.rs`: the one formatter for shortcut hints, read from the effective keymap. `wiring_tests.rs` checks what every action owes: a Commands row, a heading and title on Settings → Shortcuts, a remote decision and its keys as a hint.
  - `pane_ergonomics_tests.rs`: independent padding and active-pane outline checks (partial M2.7); `settings/interface.rs` keeps legacy uniform-padding and density-following defaults. Evidence and scope: `docs/parity-2026-11/M2.7-panes.md`. Real-font captures run individually with `REX_TEST_SNAP_DIR`, and `REX_M27_MINIMUM=1` selects 640×480.
  - `header_fading_tests.rs`: header-only default-off fading, focus combinations, unchanged terminal/cue descendants, Settings persistence/search and real-font captures (`REX_TEST_SNAP_DIR`; `REX_M27_MINIMUM=1` for 640×480). Run captures individually. `scripts/header-fading-x11.py` checks native focus and PTY input on private Rex/Xvfb. Scope/evidence: `docs/parity-2026-11/M2.7-header-fading.md`; no focus-follows-mouse feature.
  - `pane_verbs.rs`: the pane menu's Copy, Paste, Select all, Copy pane ID, Clear and Reset. `pane_header.rs`: a pane header's buttons and where the Pane headers setting puts a header. `find.rs`: the find bar, its placement and Find next / Find previous.
  - `tab_fill_tests.rs`: default-off toolbar tab sizing, persistence/search, overflow/navigation and unchanged pane geometry (partial M2.8). Real-font captures run individually with `REX_TEST_SNAP_DIR` (`REX_M28_MINIMUM=1` for 640×480); `scripts/tab-fill-x11.py` checks actual input on private Rex/Xvfb. Scope/evidence: `docs/parity-2026-11/M2.8-tab-fill.md`.
  - `tab_icons.rs`: cached, focused-first distinct existing program glyphs and the shared row/Settings preview; `interface.tab_icon_count` is 0–5 (default 1). `tab_icon_tests.rs` checks default semantics, ordering/dedup, search/save, geometry, overflow and local-only effects. Captures run individually with `REX_TEST_SNAP_DIR` (`REX_M28_MINIMUM=1` for 640×480); `scripts/tab-icons-x11.py` uses private Rex/Xvfb. Scope/evidence: `docs/parity-2026-11/M2.8-tab-icons.md`.
  - `tab_icon_colour_tests.rs`: the default-Never `interface.tab_icon_color` enum, on-screen host/session isolation, glyph-only colour effects, anchored Settings choice and shared active/inactive preview. Palette contrast checks and individual real-font captures (`REX_TEST_SNAP_DIR`, `REX_M28_MINIMUM=1`); `scripts/tab-icon-colours-x11.py` uses private Rex/Xvfb. Scope/evidence: `docs/parity-2026-11/M2.8-tab-icon-colours.md`; shell-theme styling remains deferred.
  - `tabs.rs`: the tab menu on toolbar pills and sidebar rows, moving a tab in its session's order, muting it on this client, closing the other tabs and its default title.
  - `splits.rs`: which side a new split goes on (right, left, down, up or best fit) and focus through a tab's panes. `font_size.rs`: terminal font size actions. `help.rs`: Rex help.
  - `input.rs`, `keys.rs`: workspace shortcuts first, then every other key to the focused pane's PTY; Rune key events to Rex `client.key` payloads; IME.
  - `term.rs`: one pane's view state and cell grid. Rows are text segments placed at `column × cell width`; a character joins a segment only if it advances exactly one cell; ligatures and kerning are off; rows are memoized by content.
  - `term/preview.rs`: steady Settings previews using the terminal renderer. `select_copy.rs`: release-triggered selection copying and opt-in PRIMARY ownership/paste on a dedicated clipboard worker.
  - `sprites.rs`: box-drawing and block element characters drawn as shapes on whole device pixels, as Ghostty does, instead of font glyphs.
  - `toolbar.rs`, `sidebar.rs`, `panes.rs`, `popups.rs`, `dialogs.rs`, `widgets.rs`: views on rune-kit, with design tokens pinned onto the kit in `theme.rs`.
  - `server_page.rs`: read-only Settings → Server for the active host, using only cached `HostModel.server_info`. `server_page_tests.rs` covers privacy, missing/stale facts, host isolation, navigation and local-only copy; individual real-font captures use `REX_TEST_SNAP_DIR` and `REX_M33_MINIMUM=1`. Private acceptance: `scripts/server-settings-x11.py`. Scope/evidence: `docs/parity-2026-11/M3.3-server-settings.md`.
  - `activity_list.rs`: local-only, grouped Activity popup over cached layouts/status, preserving the selected tab on host wakes and using notification navigation. `activity_list_tests.rs` covers state/filter/navigation and individual real-font captures (`REX_TEST_SNAP_DIR`, `REX_M32_MINIMUM=1`); private acceptance: `scripts/activity-list-x11.py`. Partial scope/evidence: `docs/parity-2026-11/M3.2-activity-list.md`. Activity-only elapsed labels use monotonic record ages (`connection/activity/time.rs`) and folded-tab clocks, with explicitly labeled read-back report ages and a popup-owned minute redraw. Tests/captures: `activity_list_tests.rs`, `activity_elapsed_draw`; private timestamp observation: `scripts/activity-timestamps-private.py`; meaning/evidence: `docs/parity-2026-11/M3.2-elapsed-time.md`. `activity_chip.rs` counts out-of-sight Needs you/Error tabs through the list's shared cached inventory; `toolbar.rs` draws its conditional entry point. `activity_chip_tests.rs`, individual `activity_chip_*_draw` captures (`REX_M32_MINIMUM=1`), private `scripts/activity-chip-x11.py` and `docs/parity-2026-11/M3.2-activity-chip.md` cover the chip. `connection/status_sweep.rs` reads program status once per connection for every session's panes (layouts through `prefetch.rs`; up to `status_sweep::IN_FLIGHT` (3) of its and the prefetch's reads in flight, at most one of them a layout; starts paced), so those surfaces know sessions that were never opened; a read never replaces a live report or brings back a record removed while it was out, a session a live report arrives for is read next, and a layout read only for activity is kept in `HostModel::background_views` so the app does not treat it as an opened session. `connection/status_sweep_tests.rs`, the measuring example `examples/status_sweep_probe.rs` and `scripts/status-sweep-private.py` (private benchmark and native acceptance) cover it; record `docs/parity-2026-11/M3.2-status-sweep.md`. `Workspace::session_word` (in `activity.rs`) folds a session's tab words for sidebar session rows and for Switch session rows (`Entry::tone`); `session_word_tests.rs`, captures `session_words_draw` and `switcher_session_words_draw`, record `docs/parity-2026-11/M3.2-session-words.md`.

  - `settings_view.rs`: the Settings dialog and its pages. `settings_kit.rs`: what every Settings page is built from (`page`, `section`, `card`, `footnote`, `setting`, `select_row`, `disclosure`, `segmented`, `value_popup`, `stepper`, `button`).   - `directory.rs`: the captured-target browser behind Insert path and Go to directory (folders only; types `cd <folder>` and never Enter), path splitting/sorting, POSIX quoting and recent rows; `settings/recent_paths.rs` stores up to ten paths per saved endpoint and shares the browser's refusal rules. Terminal's default-on Show recently used paths switch erases history when turned off; host removal or endpoint edit drops that host's history. `connection/directory.rs` sends only epoch-scoped `terminal.list_dir` reads. `directory_tests.rs` and the connection tests cover coalescing, errors, cancellation and paste-only insertion. Real-font captures run individually with `REX_TEST_SNAP_DIR` (`insert_path_draw_large`, `insert_path_draw_minimum`, `go_to_directory_draw_large`, `go_to_directory_draw_minimum`); private acceptance: `scripts/insert-path-x11.py`. Recent browser/Settings captures are `recent_paths{,_settings}_draw_{large,minimum}`. Scope/evidence: `docs/parity-2026-11/M3.1-insert-path.md`, `M3.1-go-to-directory.md` and `M3.1-recent-paths.md`.
  - `downloads.rs`, `downloads_view.rs`: the Download file… dialog, Downloads popover (a finished row's one action is Show in folder; there is no Open), toolbar chip state and the `downloads.directory` setting's use (also edited from Settings → Interface → Download folder, `Form::DownloadFolder`) (`toolbar::download_chip` draws the chip). `downloads_tests.rs`: headless UI tests for them. `actions.rs` has `pane.download` (`Remote::Never`).
  - `fonts.rs`, `font_picker.rs`, `font_page.rs`: cached fontconfig enumeration, anchored searchable family/fallback picker with lazy face samples, and Advanced font settings with ordered fallbacks and live metrics. `font_settings_tests.rs` and `term/typography_tests.rs` check persistence, ownership-aware resize, navigation, geometry and rendering.   - `terminal_page.rs`: Terminal settings cards and previews; `terminal_settings_tests.rs` and `term/selection_tests.rs` cover their policy and rendering.
  - `tests.rs`: headless UI tests.
- `src/bin/`: `rex-probe`, `rex-workspace-probe` and `rex-download-probe` (downloads through the real host connection), live protocol probes; `update_probe.rs` builds `rex-update-probe`.
- `examples/`: `chrome_spike` (borderless window chrome); `status_sweep_probe` (runs the real host connection against a private scratch socket for `scripts/status-sweep-private.py`; it refuses any other endpoint).
- `scripts/`: integration and acceptance checks, and the desktop installer. `download-contract.py` observes the API 13 download contract; `download-acceptance.py` drives the built binary through downloads on private servers (`private_ssh.py` is the private sshd it shares with `remote-control-acceptance.py`). `pane-padding-x11.py` checks independent padding, outline persistence, exact PTY coordinates and owned/unowned sizes on private Rex/Xvfb. `font-metrics-x11.py` checks live font metrics, owned/unowned resize and real PTY mouse coordinates with a private Rex server/Xvfb. `terminal-selection-x11.py` checks copy-on-selection, PRIMARY paste and mouse reporting with its own private Rex server and Xvfb. `tools/`: small helpers for test scripts.
- `resources/`: desktop entry and icons.
- `vendor/`: patched copies of Rune, rexrs and ghostty-vt.

## Conventions

- Match the surrounding style; run `cargo fmt` and keep clippy clean with `-D warnings`.
- Terminal content, colours and split geometry are server-owned. The client may *declare* a terminal theme through Rex's `terminal.set_theme`, which the server applies when this client owns the block or no client does, and otherwise defers until this client becomes the owner (the same rule as resize). The client never recolours terminal output locally or invents layout.
- Ordinary attachment must never start, stop or reconfigure a Rex server, and must never create or destroy a session. Creation is always an explicit user action.
- Failed input is never replayed automatically; a transport failure pauses affected panes.
- Effective workspace shortcuts consume their keys, but every binding is removable or replaceable. Keep ordinary keys flowing through `client.key`, including releases only when their press was sent. Only explicit `pane.send_key` uses `block.event` to bypass Lua bindings.
- Remote availability is decided exhaustively in `Spec::remote()`, default deny. Consent belongs to the saved host, never the requester; replies must stay on their connection epoch. Keep the allowed-set test pinned.
- Terminal content never animates; chrome motion uses the springs in `theme.rs`.
- UI changes should follow [DESIGN.md](DESIGN.md). Prefer verifying them in a rendered build (for example with Rune's `-- --snap out.png`) rather than by reading code.
- Add tests for protocol and state-machine changes; headless UI tests in `src/app/tests.rs` cover focus and dialog behavior.
- Keep the README's claims honest: don't document features that aren't implemented or checked.
- Outside pull requests are not accepted. Never ask a contributor to open a PR or invite one in issue replies; welcome issues (including issues pointing at fork commits or branches), harvest changes from forks following [`docs/fork-harvest-2026-11.md`](docs/fork-harvest-2026-11.md)'s approach (cherry-pick or rewrite what fits), credit the author with a `Co-authored-by:` trailer, and mention the author in [CHANGELOG.md](CHANGELOG.md).

## Vendored patches

`vendor/rune`, `vendor/rexrs` and `vendor/ghostty-vt` are upstream snapshots plus small, documented patches, wired in through `[patch]` in `Cargo.toml`. Rules:

- Keep each patch minimal and describe it in the vendor directory's README (`vendor/rune/README.md`, `vendor/rexrs/REX-LINUX.md`, `vendor/ghostty-vt/REX-LINUX.md`).
- Do not mix unrelated edits into vendored code; changes that could go upstream should.
- Preserve upstream license files and attribution. When bumping a pinned revision, update `Cargo.toml`, the vendored copy and its README together, then re-run the tests above.
- The Nix package (`nix/package.nix`) pins fetched sources by hash. A Rune bump also means updating the `rune-kit` hash in `cargoLock.outputHashes`; a `ghostty-vt` bump also means updating the Ghostty source archive and the Zig dependency hash there.
- Remove a patch once upstream provides an equivalent.
- Regenerate rexrs types with `python3 codegen/generate.py` (from `vendor/rexrs`) rather than editing generated files by hand.
