# Design system

Rex Linux draws calm, dark chrome around terminals that the server owns. Chrome palettes are token sets defined in `src/app/theme.rs`, which is the source of truth, and chosen at runtime (Settings → Themes → Window colours): Midnight, the default, Rosé Pine, Rosé Pine Moon and Gruvbox Dark. Their tokens are listed below (update both together). Each palette pairs with a built-in terminal theme whose background equals the chrome's ground, so a single pane reads as one surface with the toolbar. Palettes are dark only and change colours only; fills, borders, motion and layout are shared. A terminal theme may be light, and with a light and dark pair of terminal themes the one in use follows the desktop's light or dark setting; the chrome does not follow it and stays dark around a light terminal.

## Principles

- **The terminal is the content.** Chrome frames it and stays out of the way. Terminal text, colours, cursor and split geometry come from the server and are never recoloured; a terminal theme the client declares reaches the terminal through the server (Rex's `set_theme`). What the client draws itself is the user's own marks on that content, set in Settings → Terminal and never sent to a server: the selection (its fill and the text under it, from the theme or from each selected cell's own two colours) and the cursor's shape while no program has chosen one, or always with Force style. The one exception to the server's colours: the server's default terminal background is drawn in the palette's `CARD` colour (or the background of the theme this client declares), the same as the ground, so a single pane and the toolbar read as one surface. It is substituted only when both are dark or both are light, so a light default under another client's light theme, or under a server that ignored `set_theme`, keeps its own colour and the default text stays legible. Explicit background colours and inverse video's block are preserved; the substitution is by colour value, so an explicit background equal to the default is filled too.
- **Chrome moves, content doesn't.** Popups spring open from their anchor and highlights and the sidebar slide; terminal content, pane geometry and cell rendering never animate. How the chrome moves is the user's: Settings → Interface → Animation style offers Snappy (the default: `SNAPPY` 0.28 s with no bounce, `POP` 0.32 s with 12%), Natural (`NATURAL` 0.46 s with 16% bounce, `NATURAL_POP` 0.52 s with 26%) and Off, which asks Rune to reduce motion: travel, scale and shape changes land at once and opacity and colour take Rune's 180 ms fade. The desktop's reduce-motion preference does the same under any style. Views take their springs from `theme::snappy()` and `theme::pop()`, never from the constants.
- **One working row.** Session identity, tabs, commands and the window's own controls share a single toolbar, which the user may take off the screen (Toolbar → On hover or Hidden, below); it is still one row when it shows. Navigation (hosts → sessions) opens on demand, with an optional sidebar. The Sidebar tab position is an option that moves tabs out of the toolbar into the sidebar while the sidebar is open; closed, the toolbar shows them again.
- **Quiet when healthy.** A connected host, a live pane and the active tab carry no status dots or "Connected" labels; names and host icons are enough. Words appear only for trouble ("Offline", "Reconnecting", "input paused"), in `WARNING`, next to the action that fixes it. The exception is program activity: a tab whose programs finished while the user was away says "Done" in `ACCENT` until it is seen, a terminal bell that rang out of sight says "Bell" in `WARNING` until its tab is seen, and a tab whose program reports its progress (OSC 9;4) draws it as a 2 pt bar along the pill's bottom edge in `ACCENT`, with no word, until the program clears it or leaves the foreground; a paused report says "Paused" in `WARNING`, with its percentage when it gave one, and a failed one "Error" in `DANGER`, each over a bar in the same colour.
- **Distinct states.** The current session, the keyboard-selected row, a captured pane target and live terminal focus each have a different cue. Keyboard selection is never fill alone: a selected list row is the `SELECTION` tint under a 1 pt outline, which no hover uses.
- **Name the target.** Creation actions name their host; destructive confirmations name the pane, tab and host and default to **Keep running**; closing the app leaves server programs running.

| `ON_ACCENT` | Text on an accent fill (primary buttons) |
| `TERMINAL_SELECTION` | Local terminal text-selection overlay, unless the declared theme sets `selection-background` or the Selection settings take the fill from the selected cells |

Progress bars under tab pills and pane names use `ACCENT` (working), `WARNING` (paused) and `DANGER` (failed) over an 8% white track; an unknown percentage is the whole track in the report's colour at 35%. Terminal search matches are an overlay in `ACCENT` with a 2.5 pt radius, drawn like the selection: every match is a `SEARCH_MATCH` (18%) tint under a 1 pt outline at `SEARCH_OUTLINE` (70%), and the selected one is filled at `SEARCH_CURRENT` (80%). An unselected match keeps the terminal's own text colour, so its tint is light enough for dim text to stay readable and the outline carries the mark. The selected match's text is drawn in `ON_ACCENT`, as selected text takes a theme's selection foreground, because light terminal text cannot be read on that mark; a selection over it wins. No other cell colour changes, and the terminal is never dimmed while it is searched. Terminal cursors, underline colours and overlines come from the terminal, never from these tokens.

The paired terminal themes are Midnight (its navy behind Rex's default text), Rosé Pine and Rosé Pine Moon as their Ghostty themes draw them, and Gruvbox Dark's background, text, cursor and 16-colour palette. In every palette `MUTED` on `CARD` and `INK` on `POPOVER` meet WCAG AA (4.5:1); `WARNING` and `DANGER` are at least 3:1 on both surfaces (Gruvbox Dark's red is the lowest, 4.3:1 on its ground and 3.4:1 on popovers) and always carry a word. Switching palettes is instant: colours change in one frame, with no crossfade.

Interaction fills are translucent white over the surface: hover 7%, pressed 11%; borders 6–20% white (focus uses `ACCENT`). Trouble states always carry a word, never colour alone; healthy states show nothing. There is no light chrome palette.

## Typography

Chrome uses Inter (bundled with the kit) in 10–13 pt steps, weights about 450 (body), 560 (medium), 620 (strong); group labels are 10.5 pt small capitals with 0.6 tracking, and a name inside a popup's group label (a host, a session, a tab) is not capitalised. The terminal family, ordered fallback families and size (8–48 px) are saved locally, and `--font`, repeated `--font-fallback` and `--font-size` override them for one launch; the default is JetBrainsMono Nerd Font 15. Missing glyphs come from the named fallbacks in order, then bundled IBM Plex Mono, then the system's script and symbol fallbacks; an unavailable primary is replaced by IBM Plex Mono. Family and fallback changes apply after reopening the client; the rest of the typography applies to every terminal as it changes. The cell is the primary font's advance plus the character spacing (−3 to +12 pt, or −30% to +100% of the advance; 0 by default) wide, and 1.4 × the size, scaled by the line height adjustment (−20% to +100%; 0 by default), in whole points tall. The added spacing is shared between a glyph's two sides, and the text sits in the middle of a taller row with its underlines and overlines. Box drawing, block elements, the cursor, the selection and search marks are drawn from the cell, so they fill it at any setting, and a pane this client sizes is told its new rows and columns at once. Ordinary text is drawn in the family's Regular, Italic, Bold or Bold Italic face (Regular by default), and the bold and italic attributes programs set are both drawn unless Settings says otherwise. Ligatures and kerning are off so the grid stays exact. Names keep their case and ellipsize when space is bounded, with tooltips for the full text. Server windows are called **tabs**.

## Layout and shape

- **Toolbar:** 52 pt chip bar. Controls sit on glassy chips (10 pt radius, 5.5% white fill, gradient hairline border). The tab track is one too, as a capsule: 34 pt tall with a 17 pt radius, holding tab pills that are 30 pt capsules 2 pt in, so a pill's ends are concentric with the track's. Pills are 96–240 pt wide. A pill ends in a close button, a 12 pt × in an 18 pt round target 6 pt from the pill's end: always on the tab on screen, and on any other tab only while the pointer is over that tab. Every pill keeps the room for it, so nothing moves when it shows and a tab is as wide on screen as off. It asks before closing, as the tab's right-click menu, a middle-click and `Ctrl Shift W` do, and it is the pointer's alone: the Tab key never lands on it. The tab menu is grouped by hairlines, safest first and Close last: Rename tab… and Mute tab; Move left and Move right (Move up and Move down when tabs are listed in the sidebar), disabled at the ends of the order; New tab; Close other tabs… and Close tab…, both destructive rows in `DANGER`. The tab a menu, rename form or close confirmation acts on carries a 1.5 pt `ACCENT` outline. A muted tab shows a 14 pt `MUTED` crossed bell where its activity word would be, and no word or progress bar. Commands (⌘), New tab (+) and Settings (a gear) sit at the right end with Close, all as bare 15 pt icons on a 36 pt pitch with no fill at rest; hovering shows the same 30 pt round fill on each (9% white, `DANGER` at 22% for Close). A 1×16 pt hairline divides the app's buttons from Close. There are no minimize or maximize buttons: tiling window managers often ignore them. A pill shows its focused pane's program icon, its label, and then a word for program activity (Settings → Interface → Customize tabs can change the icons: see Tab icons below): "Needs approval", "Question", "Needs sign-in" or "Needs input" in `WARNING`, "Error" in `DANGER`, unseen "Done" in `ACCENT`; idle and working tabs show no word (a working program's progress is the bar under the label, never a word). A tab still called "Shell", the name new tabs get, shows its focused pane's terminal title instead while the program that set it is in the foreground; a tab the user named keeps its name. With Settings → Terminal → Prefer generated titles on (off by default), such a tab, and a pane that still has its default label, is called by its foreground program and that program's directory instead (`vim - ~/rex`, the home directory as `~`, and of a path longer than 24 characters only the last folders that fit, after `…/`) wherever its only title is one the terminal's own shell set, or it has none. A title a program set for itself still shows, and so does every name the user gave. The same name is used on the pill, the pane header, the sidebar row, the window title, menus and notifications. It is a display choice: no label or title on the server changes. The label truncates before the word does; the program's message is the word's tooltip. The empty space moves the window; edges and corners resize it. Settings → Interface → Toolbar offers Always show (default), On hover and Hidden. On hover and Hidden give the toolbar's 52 pt to the panes: a single pane then reaches the window's top edge, and pane cards and the sidebar keep the 10 pt outer margin from it. On hover floats the toolbar over the top of the window, on `POPOVER` with a hairline under it and a shadow, sliding in from the edge, once the pointer has rested 80 ms in the window's top 8 pt (thinner than the default padding above a terminal's first row), and it leaves 320 ms after the pointer leaves the toolbar; a pass over the edge or a press in it shows nothing and goes to what is under it. Reveal toolbar (`client.toolbar.toggle`, `Ctrl Alt Shift T` by default, and in Commands) floats it in either until it is run again, and is not saved: it is how a window with no toolbar row is dragged and closed, and Settings names it under the Toolbar row with its current key. A floating toolbar never moves or resizes a terminal. With no toolbar on screen a waiting key sequence's chip floats alone at the window's top-left corner on `POPOVER`, notices take the window's top-right corner, and Settings may use the whole height. The identity chip is as wide as its words, between 120 and 210 pt, where a longer name truncates: the session's name on one line, with the host's kind icon and a chevron. A second line names the host only when it says something: in `MUTED` while another host is connected too, and in `WARNING` with "Reconnecting" while its own host is not.
- **Window title:** `<tab> - <session> · <host>`, the tab named as on its pill, so a task switcher tells one window's shell from another's; `Rex · <host>` until a session is chosen.
- **Terminal search:** `Ctrl Shift F` opens the find bar: 320×34 pt (narrower in a narrower pane), 6 pt in from the right edge of the terminal's top-right corner, opaque `POPOVER` with a 1 pt hairline and an 8 pt radius. The bar takes whole rows and whole columns: an apron in the terminal's own background lies under it, from the pane's edge to the first column boundary at least 3 pt past the bar and over as many rows as hold the bar with 3 pt above and below, and the bar is centred on those rows. So no sliver of a row or half a glyph shows beside the bar, at any font size. The apron hides cells and never recolours them; it changes corner at once while the bar springs, and a press on it is the terminal's. From the left: the magnifier and field (`Search terminal`), the selected match's place among all matches (`2/5`, 11 pt `MUTED`) or "No matches" in `DANGER`, nothing while the field is empty; a 1×16 pt hairline; then Find next (up: the older match), Find previous (down: the newer one) and Close, as 24 pt buttons like a pane header's. The arrows keep their place at 35% opacity while there is nothing to step through. Tooltips name the field's key and then the action's own while it has one (`Find next · Enter · F3`, `Close search · Esc`). A press on the bar never takes the keyboard from the field or the terminal and never reaches the program. The bar never covers the selected match: when that match's cells are under its apron, it springs (`SNAPPY`) to the first corner that leaves them in view, trying bottom-right, top-left, then bottom-left, and stays there until a selected match is under it again; closing sends it home. It floats over the terminal and never moves or resizes it, and its rows start at the first row below the exception strip where that floats in the same corner. Find next and Find previous are actions too (`client.search.next`, `client.search.previous`, no default keys, in Commands): they step an open bar wherever the keyboard is, and bring a closed one back on the pane's last searched text without focusing it, so a search's marks are never on screen without the bar that explains and ends them. While the field holds the keyboard, the terminal's cursor is the hollow outline of a pane without it.
- **Single pane:** a tab with one pane, not zoomed, draws it edge to edge under the toolbar with no card, header, border or margin. Its exception strip floats at the pane's top-right corner. Only Pane headers → Always gives it a card and a header.
- **Pane density:** Settings → Interface offers Compact and Comfortable (default). Compact uses server-defined placements without outer borders, shadows, rounded corners, gutters or outer margins, and without headers unless Pane headers says otherwise; terminal padding stays. Each split boundary has one permanent straight 1 pt separator, with no border around individual panes. Divider hit areas remain over the boundaries, a pane with no header floats its exception strip at its top-right corner, and pane menus retain a square target outline. Focus is shown by the terminal cursor, and by a pane border only when Highlight active pane is switched on: then the focused pane of a tab with several has a flat 1 pt `ACCENT` outline at 85% inside its edges. Per-pane activity words and progress bars live in the header, so they show only where one does; tab activity remains.
- **Pane headers:** Settings → Interface → Pane headers offers Auto (default), Always, On hover and Hidden. Auto follows the density: a header row on the cards of a split or zoomed tab in Comfortable, none in Compact, none on a single pane. Always puts the row on every pane in either density, a single one included, which then is a card. On hover draws no row; resting the pointer for 90 ms in the top 36 pt of a pane floats the header over the terminal's top edge, on `POPOVER` with a hairline under it, and it leaves 220 ms after the pointer does. Hidden draws none. A floating header never moves or resizes the terminal under it, takes no presses until it shows (a pass through the band or a press in it goes to the terminal), and stays away while that pane's search field is open. Reveal pane headers (Commands, `client.pane_headers.toggle`, no default key) floats the header on every pane without a row until it is run again; it is not saved. The header is 30 pt: the pane's name (14 pt from the edge), a `Zoomed` chip (18 pt, keycap fill) while the pane fills its tab, the activity word, then at the trailing end the exception strip, the progress bar and four buttons: Split right, Split down, Zoom (Restore while zoomed) and Close. Buttons are 24 pt targets with 14 pt icons, 8 pt from the edge so a hover fill stays clear of the card's 12 pt corner, `MUTED` at rest (70% on panes without focus) and `INK` under the pointer on a 9% white rounded fill; Close's fill is `DANGER` at 22%. They act on their own pane, focused or not, never keep focus, and show their shortcut in the tooltip. An action that cannot run keeps its place at 35% opacity with the reason as its tooltip: Zoom, on the only pane of a tab. The pane menu's Zoom pane row and Commands' follow the same rule. Close opens the confirmation that names the pane, tab and host. Under 200 pt wide a header keeps Zoom and Close only.
- **Pane cards:** in Comfortable density, splits, and a zoomed pane, are server-defined placements as rounded cards (12 pt radius) with, where Pane headers puts one, a 30 pt header (pane name, its program's activity word, when needed its exception strip, and the pane's buttons), 8 pt gutters and 10 pt outer margin on the ground; their border separates them from the same-coloured ground. Terminal content has padding on all four sides in every pane (including below a split card's header), set in Settings → Interface → Customize panes → Padding as Horizontal padding (the sides) and Vertical padding (above and below), each 0–32 pt and 8 pt by default; zero removes content padding but keeps card borders; a terminal background other than `CARD` fills the card's body inside its border, below the header, with the card's bottom corners (and its top corners where there is no header row). Divider drags preview immediately and send a ratio clamped to 0.1–0.9. The header's word is the tab's word for that pane alone (trouble and progress; Done and Bell stay with the tab), follows **Show activity in tabs**, carries the program's message as its tooltip, and stays whole while the name truncates. A pane whose label is still its terminal's default (`shell`, the last word of its flavor) shows its program's terminal title while that program is in the foreground, as a "Shell" tab does; a renamed pane keeps its name, and a pane renamed to exactly `shell` counts as unrenamed. The title is display only: the server label is never changed, and Rename starts from it.
- **Tab icons:** a tab shows one 15 pt icon for each program in its panes, the focused pane's first and the rest in the server's order, up to the number chosen in Settings → Interface → Customize tabs (0 to 5, default 1); panes that would show the same icon share one, so two shells are one prompt. The first icon, which is what the tab is doing, sits on a badge: a 20 pt rounded square (6 pt radius, 6% white), 6 pt from the pill's start; a rounded square so it is never taken for a button. Icons sit 6 pt apart, before the 8 pt gap to the label, and each names its program in a tooltip. By default an icon is in its tab's own ink (`INK` on the tab on screen, `MUTED` on the others), as every other icon in the chrome is. Colour is a choice, and the only colours in the chrome that are not palette tokens: Always, Active pane (the focused pane's icon in the tab on screen), Active tab (every icon of the tab on screen) or Never, the default. In colour, a program's icon takes that program's tint, a fixed colour that is at least 3:1 against every palette's `GROUND` and against the pill of the tab on screen; programs are still told apart by the icon's shape, never by colour alone. A shell's icon in colour is a prompt on a tile: its badge in the tile's colours when the shell is the tab's first icon, and otherwise a tile of the badge's size drawn around the icon's box as an overlay, so a tab is the same width in colour and out of it. The tile has three looks: Default (a green prompt on 42% black with a 10% white edge), Terminal theme (the theme's background, an edge 16% of the way to its text colour, and its green for the prompt, or its text colour where the green is under 3:1 on that background; Follow server has no colours, so it keeps the default tile) and Accent (`ACCENT` on the default tile). Tabs listed in the sidebar draw the same icons. With **Tabs fill the toolbar** on, the track takes all the room between the identity chip and the buttons but a fixed 48 pt of drag space, and its tabs share it equally with their content centred between the room for the × and as much again at the start; a tab is never narrower than 96 pt, or than its icons, 40 pt of its name and its whole activity word need, and a strip whose tabs are all at that floor scrolls as before. Off (the default), tabs are as wide as their content, between 96 and 240 pt.
- **Sidebar:** optional; it opens at launch as it was left, at its saved width. Default 236 pt wide (200–360 pt, drag the edge to resize, double-click to reset). Host rows are 28 pt, session rows 32 pt, groups separated by 12 pt. A session row counts its tabs at the right edge only above one tab; a lone tab is what a session has, so it gets no number. With the Sidebar tab position, a session's row becomes a 24 pt muted label and its tabs follow as 32 pt rows indented 12 pt, each with the toolbar pill's icon, label and activity word; the active tab gets the pill's fill and hairline. A tab row has the pill's interactions: right-click for the tab menu (acting on that row's tab in its own session), double-click to rename, middle-click to close behind the confirmation.
- **Popovers:** session/host menus anchor to the identity; pane and tab menus to the pointer (right-click), and pane menus also to the toolbar; the command menu is centered near the top. Popovers are compact: the session switcher and the theme switcher 340 pt wide, Commands 460, the Add host list 520, pane, tab, session and host menus 280; 28 pt rows (30 in Commands), 26 pt group headers, a 34 pt search field, 5 pt padding and a 12 pt radius. Popovers clamp to the viewport; long lists scroll under a 10 pt edge fade with directional hints that count hidden rows. The selected row is `SELECTION`, and the selection follows the pointer, so exactly one row is lit. A row ends with its shortcut and then a 14 pt column for the chevron of rows that open a dialog or another list; the column is kept on every row, so hints end on one line. A switcher session row ends with the key that shows it while the switcher is open: the effective binding of Go to session for its place among the rows a filter leaves (`Ctrl 1` to `Ctrl 9` by default), so the numbers always count what is listed. In Commands, Ctrl Enter opens the highlighted command's row in Settings → Shortcuts with its recorder open; it is a reserved popup key, like Enter, and is named in that page's opening paragraph rather than in a footer. A row with no action says so in a notice and Commands stays. The theme switcher (Change theme… in Commands, `client.theme.choose`, or the Terminal theme row in Settings) is at most 420 pt tall with its search field and hint line, and scrolls to the rest; it checks the theme in use in that last column, at the end of its row, so names start on one line with no column before them. Before that column each row ends with its colours as a strip: a 44×14 pt capsule in the theme's background, with a 1 pt edge 16% of the way to its text colour, holding four 6 pt dots (its text colour, then its red, green and blue). Follow server has no colours of its own, so its strip is the capsule's outline alone and the strips keep one column. A terminal theme found by a Commands search has the same strip, and a window-colours row there and in the Window colours list has its palette's: `GROUND` holding `INK`, `ACCENT`, `ACCENT2` and `LIVE`. A search for names (the theme switcher; themes and window colours in Commands) ignores case and accents and takes its words in any order; the letters that matched are drawn in `ACCENT` at weight 650, told apart by weight as well as colour, and halfway from `ACCENT` to `INK` on the selected row, whose tint is `ACCENT` too. A popover never opens another popover from its rows: the switcher's highlighted session row trades its detail for pencil and × buttons, and renaming turns the row itself into a field (accent outline) until Enter or Esc.
- **Menus** are grouped: a 1 pt hairline (9 pt with its margins) separates one group of rows from the next, and a filtered list is flat, with no hairlines. The pane menu's groups are clipboard (Copy, Paste, Select all), layout (Split right, left, down and up, then Zoom pane), the pane (Rename pane…, Copy pane ID), its terminal (Clear terminal, Reset terminal, Reconnect terminal) and Close pane…. A row that cannot run now stays in its place in `MUTED` (Copy with nothing selected; Paste, Clear and Reset on a terminal that is not live; Zoom pane on the only pane of a tab), and a menu opens on its first row that can. The rows that end something (Close pane…; Close other tabs… and Close tab…; Close session…; Remove host…) are the last group of their menu, after a hairline, with their labels in `DANGER`; an unavailable one is `MUTED` like any other. On a destructive row the selection tints in `DANGER` and the label turns `INK`.
- **Commands** groups every command by what it acts on, in this order: Session, Tab, Pane, Host, Server actions (only when the host offers any), View, Appearance and App. View is what the window shows (the sidebar, where tabs are listed, pane headers); Appearance is how it looks: Change theme… and Change window colours…, then the pane style, the interface zoom and the terminal font size, each after a hairline. A heading names what is on screen ("Tab · dev", "Host · workstation"): the group's word is in small capitals and the name beside it keeps the case it was given, in 11 pt medium `MUTED`, as a host's name does in the switcher's headings; the Pane group is left out when there is no pane, and a command that cannot run now stays in place, disabled. Within a group the order is create and navigate first and the rows that end something (Close…, Remove…) last, after a hairline and in `DANGER` as in a menu. The Pane group lists the pane menu's rows in the menu's order, with hairlines between the same groups, and adds what acts on the focused pane: Search terminal…, Find next and Find previous after the clipboard rows, Split best fit (right of a pane wider than tall, otherwise below) with the other splits, the focus moves, which are disabled in a tab with one pane, then Move pane and Resize pane toward each side, each disabled where no pane lies or no border can move that way, and Close pane or tab… and Close other panes… beside Close pane…. Typing replaces the headings and hairlines with one list under "Commands", best match first (the command named exactly, then a label that starts with the query, then one whose words do, then one that contains it, then a match in the group's name or the command's other names), followed by the matching sessions and tabs under their own headings, and then, from two letters on, an Appearance heading with the window colours and the terminal themes whose names have a word starting with each word typed. Such a row says which it is where a shortcut would be ("Window colours", "Terminal theme"), applies at once and closes Commands, and the one in use is checked in the chevron's column. Follow server, Rex default colours and Follow chrome are not names to search for and stay in the switcher. Commands shows about twenty rows and scrolls to the rest; its hint names the groups whose heading is still below ("More below: Host · View · Appearance · App"), never one whose heading is already on screen; when only the rest of such a group is left it says so ("More App commands below"). A row's hint is its action's effective binding, drawn as keycaps, a host's own actions included; a row without a binding shows none, or a few words where they help (Close app: "Programs keep running"). ## Interaction

- Workspace defaults are listed in the README; every binding is removable or replaceable. A default never takes a key programs use for an action that belongs to one moment: such a binding carries a `when` and is tried only then (`F3` and `Shift F3` step through matches while the find bar is open; `Ctrl 1` to `Ctrl 9` pick a session in the switcher, where a key that would type into the filter is never taken), and at any other time its key goes to the terminal like an unbound one. A hint for such a key shows only while it would run. The active host’s effective map drives dispatch, Settings and Commands; unbound keys reach the terminal through `client.key`. Only popup editing/navigation and Escape cancelling a sequence remain reserved. Every shortcut hint comes from the effective keymap through one formatter (`keycaps.rs`), in one spelling (`Ctrl Shift D`; `Ctrl B, C` for a sequence): menu rows, Commands, the switcher, the sidebar's Find a session chip, toolbar tooltips and the empty workspace's text. No hint is written out by hand, so a rebind shows everywhere at once. In lists and the sidebar a hint is drawn as keycaps: one 17 pt chip a key (7% white, 10.5 pt text halfway from `MUTED` to `INK`, which meets 4.5:1 on its chip in every palette; `INK` on a 12% chip in the selected row), the chords of a sequence joined by a muted "then". A tooltip names its control and then the keys (`New tab · Ctrl Shift T`). Commands details use the highest effective binding for their action and args (among an action's default bindings that is the main block's key, not the numpad's); unbound actions have no keyboard hint, in a row or a tooltip, while mouse Back/Forward show literal pointer hints as plain text until they are given a key. The reserved popup keys are keycaps too (`Esc` in a search field, `Enter` in an inline rename). Ctrl Tab and Ctrl Shift Tab traverse connected hosts, sessions and cached tabs in sidebar order, wrapping; an uncached session is one stop. Cross-session cycling settles for 150 ms before attachment, without animating terminal content. Mouse Back and Forward revisit window-local history and never reach terminal mouse reporting or navigate behind a panel. Commands exposes the same named navigation actions; Ctrl PageUp and PageDown remain server-controlled within the current session.
- SSH setup is separate from attachment: a missing default server offers **Start personal server…**, then a dialog names the host, full endpoint, exact command and effects. **Not now** is the default; only **Start personal server** authorizes a one-time attempt. Busy setup disables repeated starts, errors remain in the dialog, and closing a busy dialog does not claim to cancel the remote start. No automatic future start or installer prompt approval is implied.
- Opening a form or search focuses its first field; close confirmation focuses **Keep running**. Tab and Shift-Tab cycle fields and actions in panels; Enter and Space activate; Escape backs out and restores the previously focused pane. Tab, Space, Return, Escape and Menu never move focus away from the terminal unless a panel is open.
- Right-click captures the specific pane under the pointer; its menu names tab and pane and keeps a target outline through rename and close. A target that disappears dismisses the menu with a notice instead of retargeting.
- Size ownership is automatic and has no control of its own: the window claims the panes on screen when it comes forward, and typing or pasting in a pane claims that pane. A pane another client has claimed since is left alone until then: it draws at that client's size and never sends a resize. A reconnecting terminal shows an exception strip with **Retry**.
- A transport failure marks affected panes input-paused, keeps their output, and never queues or replays input. Notices are toasts: errors are sticky, information leaves after about 6 seconds, and at most three notices are retained. A verified release update adds one non-blocking update toast (accent dot, channel-specific upgrade summary, **What's new**, **Updates…** and dismiss-for-this-version) and a **Settings → Updates** section with **Copy command** and opt-out; background update check failures are silent and never produce a toast.
- Remote control is a per-host switch in Settings → Remote Hosts, off by default, with a Commands toggle for the host on screen. The client label is editable there too. No healthy-state badge: each performed request gets one six-second notice naming host, requester and action. Off explains itself once per host per launch; other refusals are quiet. Requests never raise the window or open a dialog.
- Focus cues: the focused terminal draws the cursor shape its program asked for (a filled block unless it chose a bar or underline), other panes, and every pane while the window has no focus, a hollow outline block, and a pane has an accent outline when focused and no panel is open, where Highlight active pane says so: on Comfortable's cards (a gradient hairline and a soft glow) and off on Compact's flush panes until the user switches it, and then the same in both. A tab's only pane, edge to edge, is never outlined. Fade inactive pane headers and Fade headers in inactive windows (both off by default) draw the name, `Zoomed` chip and buttons of a header at 45%: on panes without the keyboard, and on every pane while the window is not the active one. Only that chrome fades; terminal content is never dimmed, and the activity word, progress bar and exception strip keep full strength, because trouble is never dimmed. Focus follows mouse (off by default) focuses the pane the pointer has rested on for 60 ms, through the request a header press sends; it never claims size ownership, and does nothing while a panel is open, a divider is dragged or the window is not the active one. Cursor blink requests draw steadily, like the rest of terminal content. Settings → Terminal → Cursor style chooses the shape drawn until a program asks for one (a block by default), and Force style keeps it whatever a program asks; the hollow block of a pane without the keyboard is not a setting.
- Terminal selection: one shape per row over the selected cells, in `TERMINAL_SELECTION` or the theme's colour, or one per run of cells that fill alike when the fill is the cells' own colour. With Rounded corners (the default) the outer corners of the whole selection have a 3 pt radius and the corners where one row's selection meets the next stay square, so a selection of several rows reads as one shape. Selected text whose colour would equal its fill takes the cell's other colour.
- Links open only on Ctrl+click (press and release on the same link), never on a plain click, so selecting text and clicking into programs stay unchanged. Holding Ctrl over a link underlines it in its own text colour, shows the hand pointer and gives it a tooltip with its target URL (never its displayed text).

## Do and don't

- Do keep the toolbar single-row and the terminal canvas dominant; a toolbar the user hid floats over the panes when it shows and never takes its row back.
- Do take chrome springs from `theme::snappy()` and `theme::pop()`, so they follow Animation style.
- Do keep chrome tokens in `theme.rs` rather than hard-coding colours in views.
- Do derive overflow cues and hidden-row counts from measured content.
