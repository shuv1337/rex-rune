# Design system

Rex Linux draws calm, dark chrome around terminals that the server owns. Chrome palettes are token sets defined in `src/app/theme.rs`, which is the source of truth, and chosen at runtime (Settings → Interface → Theme): Midnight, the default, Rosé Pine, Rosé Pine Moon and Gruvbox Dark. Their tokens are listed below (update both together). Each palette pairs with a built-in terminal theme whose background equals the chrome's ground, so a single pane reads as one surface with the toolbar. Palettes are dark only and change colours only; fills, borders, motion and layout are shared.

## Principles

- **The terminal is the content.** Chrome frames it and stays out of the way. Terminal text, colours, cursor and split geometry come from the server and are never recoloured; a terminal theme the client declares reaches the terminal through the server (Rex's `set_theme`). The one exception: the server's default terminal background is drawn in the palette's `CARD` colour (or the background of the theme this client declares), the same as the ground, so a single pane and the toolbar read as one surface. It is substituted only when both are dark or both are light, so a light default under another client's light theme, or under a server that ignored `set_theme`, keeps its own colour and the default text stays legible. Explicit background colours and inverse video's block are preserved; the substitution is by colour value, so an explicit background equal to the default is filled too.
- **Chrome moves, content doesn't.** Popups spring open from their anchor and highlights and the sidebar slide; terminal content, pane geometry and cell rendering never animate.
- **One working row.** Session identity, tabs, commands and the window's own controls share a single toolbar. Navigation (hosts → sessions) opens on demand, with an optional sidebar. The Sidebar tab position is an option that moves tabs out of the toolbar into the sidebar while the sidebar is open; closed, the toolbar shows them again.
- **Quiet when healthy.** A connected host, a live pane and the active tab carry no status dots or "Connected" labels; names and host icons are enough. Words appear only for trouble ("Offline", "Reconnecting", "input paused"), in `WARNING`, next to the action that fixes it. The exception is program activity: a tab whose programs finished while the user was away says "Done" in `ACCENT` until it is seen, a terminal bell that rang out of sight says "Bell" in `WARNING` until its tab is seen, and a tab whose program reports its progress (OSC 9;4) draws it as a 2 pt bar along the pill's bottom edge in `ACCENT`, with no word, until the program clears it or leaves the foreground; a paused report says "Paused" in `WARNING`, with its percentage when it gave one, and a failed one "Error" in `DANGER`, each over a bar in the same colour. The download chip (`↓ build.log 42%`, or `↓ 3 files`) exists only while bytes are arriving, like the pending-sequence chip (a transfer still waiting for Rex or for an answer to a question has its dialog instead). The tab strip gives way to every chip, so below 1000 pt of window, or while a key sequence is pending, it shortens to `↓ 42%` (`↓ 3`), and in a narrow window it steps aside for the pending-sequence chip; the active tab is scrolled back into view whenever a chip comes or goes: a finished transfer leaves one notice and no trace in the bar, and nothing is opened or shown in a folder until its row is clicked.
- **Distinct states.** The current session, the keyboard-selected row, a captured pane target and live terminal focus each have a different cue. Keyboard selection is never fill alone: a selected list row is the `SELECTION` tint under a 1 pt outline, which no hover uses.
- **Name the target.** Creation actions name their host; destructive confirmations name the pane, tab and host and default to **Keep running**; closing the app leaves server programs running.

## Colour

| Token | Use |
| --- | --- |
| `GROUND` | Window ground and page background |
| `CARD` | Pane cards; the terminal's default background when it is dark and no theme with its own background is declared (the same colour as the ground, and the paired terminal theme's background) |
| `POPOVER` | Popovers, dialogs, raised surfaces (drawn at 95% over a backdrop blur) |
| `INK` | Primary text and icons |
| `MUTED` | Secondary text, labels, hints and icons |
| `ACCENT` | Focus, selection, current-session emphasis, caret, terminal search matches |
| `SELECTION` | The keyboard-selected row of a list: `ACCENT` at 18% under a 1 pt `ACCENT` outline, text in `INK`; on a destructive row the tint and outline are `DANGER` |
| `ACCENT2` | Secondary accent |
| `LIVE` | Kit success colour |
| `WARNING` | Reconnecting strips, notices, trouble words and state chips that need the user |
| `DANGER` | Validation errors, destructive text and the selection of a destructive row |
| `ON_ACCENT` | Text on an accent fill (primary buttons) |
| `TERMINAL_SELECTION` | Local terminal text-selection overlay, unless the declared theme sets `selection-background` |

Progress bars under tab pills and pane names use `ACCENT` (working), `WARNING` (paused) and `DANGER` (failed) over an 8% white track; an unknown percentage is the whole track in the report's colour at 35%. Terminal search matches are an overlay in `ACCENT` with a 2.5 pt radius, drawn like the selection: every match is a `SEARCH_MATCH` (18%) tint under a 1 pt outline at `SEARCH_OUTLINE` (70%), and the selected one is filled at `SEARCH_CURRENT` (80%). An unselected match keeps the terminal's own text colour, so its tint is light enough for dim text to stay readable and the outline carries the mark. The selected match's text is drawn in `ON_ACCENT`, as selected text takes a theme's selection foreground, because light terminal text cannot be read on that mark; a selection over it wins. No other cell colour changes, and the terminal is never dimmed while it is searched. Terminal cursors, underline colours and overlines come from the terminal, never from these tokens.

The paired terminal themes are Midnight (its navy behind Rex's default text), Rosé Pine and Rosé Pine Moon as their Ghostty themes draw them, and Gruvbox Dark's background, text, cursor and 16-colour palette. In every palette `MUTED` on `CARD` and `INK` on `POPOVER` meet WCAG AA (4.5:1); `WARNING` and `DANGER` are at least 3:1 on both surfaces (Gruvbox Dark's red is the lowest, 4.3:1 on its ground and 3.4:1 on popovers) and always carry a word. Switching palettes is instant: colours change in one frame, with no crossfade.

Interaction fills are translucent white over the surface: hover 7%, pressed 11%; borders 6–20% white (focus uses `ACCENT`). Trouble states always carry a word, never colour alone; healthy states show nothing. There is no light chrome palette.

## Typography

Chrome uses Inter (bundled with the kit) in 10–13 pt steps, weights about 450 (body), 560 (medium), 620 (strong); group labels are 10.5 pt small capitals with 0.6 tracking, and a name inside a popup's group label (a host, a session, a tab) is not capitalised. The terminal family, ordered fallback families and size (8–48 px) are saved locally, and `--font`, repeated `--font-fallback` and `--font-size` override them for one launch; the default is JetBrainsMono Nerd Font 15. Missing glyphs come from the named fallbacks in order, then bundled IBM Plex Mono, then the system's script and symbol fallbacks; an unavailable primary is replaced by IBM Plex Mono. Family changes apply after reopening the client. Cell width follows the primary font's advance; ligatures and kerning are off so the grid stays exact. Names keep their case and ellipsize when space is bounded, with tooltips for the full text. Server windows are called **tabs**.

## Layout and shape

- **Toolbar:** 52 pt chip bar. Controls sit on glassy chips (10 pt radius, 5.5% white fill, gradient hairline border). Tab pills are 96–240 pt wide with no close button: a tab closes from its right-click menu, a middle-click or `Ctrl Shift W`. The tab menu is grouped by hairlines, safest first and Close last: Rename tab… and Mute tab; Move left and Move right (Move up and Move down when tabs are listed in the sidebar), disabled at the ends of the order; New tab; Close other tabs… and Close tab…, both destructive rows in `DANGER`. The tab a menu, rename form or close confirmation acts on carries a 1.5 pt `ACCENT` outline. A muted tab shows a 14 pt `MUTED` crossed bell where its activity word would be, and no word or progress bar. Commands (⌘), New tab (+) and Settings (a gear) sit at the right end with Close, all as bare 15 pt icons on a 36 pt pitch with no fill at rest; hovering shows the same 30 pt round fill on each (9% white, `DANGER` at 22% for Close). A 1×16 pt hairline divides the app's buttons from Close. There are no minimize or maximize buttons: tiling window managers often ignore them. A pill shows its focused pane's program icon, its label, and then a word for program activity: "Needs approval", "Question", "Needs sign-in" or "Needs input" in `WARNING`, "Error" in `DANGER`, unseen "Done" in `ACCENT`; idle and working tabs show no word (a working program's progress is the bar under the label, never a word). A tab still called "Shell", the name new tabs get, shows its focused pane's terminal title instead while the program that set it is in the foreground; a tab the user named keeps its name. The label truncates before the word does; the program's message is the word's tooltip. The empty space moves the window; edges and corners resize it. The identity chip is as wide as its words, between 120 and 210 pt, where a longer name truncates: the session's name on one line, with the host's kind icon and a chevron. A second line names the host only when it says something: in `MUTED` while another host is connected too, and in `WARNING` with "Reconnecting" while its own host is not.
- **Toolbar visibility:** Interface offers Always show (the existing 52 pt row), Show on hover and Hidden. The latter two reserve no toolbar height. Show on hover uses an 8 pt position-tracking top band behind the panes and toolbar, preserving left-clicks and context menus, with 80 ms reveal and 320 ms leave delay. Reveal toolbar (`client.toolbar.toggle`, local-only) pins it temporarily in either mode. Floating uses `POPOVER`, the current chrome spring and shadow, never transforms or resizes terminal content; hidden controls are absent, not transparent hit targets. Pending-sequence and receiving-download chips float at the top left while the toolbar is absent; notices stay at their chosen corner. Settings uses the reserved row height, not transient hover height, so hovering cannot move a modal. Window-manager Move/Close, Settings and Commands remain keyboard paths. No Left/Right rail.
- **Window title:** `<tab> - <session> · <host>`, the tab named as on its pill, so a task switcher tells one window's shell from another's; `Rex · <host>` until a session is chosen.
- **Generated titles:** Settings → Terminal → Titles has one switch, **Prefer generated titles**, off by default. For default tab and pane labels it replaces an absent or own-shell title with the foreground program and directory (`vim - ~/rex`). A user label or program-set title still wins; unknown title ownership is preserved. Every title surface uses the same resolver, including pane menus and the window title. Home comes from that terminal's server metadata, never the client's home; long paths keep their trailing folders after `…/`. Nothing renames a server label, and rename fields still start from the saved label.
- **Terminal search:** `Ctrl Shift F` opens the find bar: 320×34 pt (narrower in a narrower pane), 6 pt in from the right edge of the terminal's top-right corner, opaque `POPOVER` with a 1 pt hairline and an 8 pt radius. The bar takes whole rows and whole columns: an apron in the terminal's own background lies under it, from the pane's edge to the first column boundary at least 3 pt past the bar and over as many rows as hold the bar with 3 pt above and below, and the bar is centred on those rows. So no sliver of a row or half a glyph shows beside the bar, at any font size. The apron hides cells and never recolours them; it changes corner at once while the bar springs, and a press on it is the terminal's. From the left: the magnifier and field (`Search terminal`), the selected match's place among all matches (`2/5`, 11 pt `MUTED`) or "No matches" in `DANGER`, nothing while the field is empty; a 1×16 pt hairline; then Find next (up: the older match), Find previous (down: the newer one) and Close, as 24 pt buttons like a pane header's. The arrows keep their place at 35% opacity while there is nothing to step through. Tooltips name the field's key and then the action's own while it has one (`Find next · Enter · F3`, `Close search · Esc`). A press on the bar never takes the keyboard from the field or the terminal and never reaches the program. The bar never covers the selected match: when that match's cells are under its apron, it springs (`SNAPPY`) to the first corner that leaves them in view, trying bottom-right, top-left, then bottom-left, and stays there until a selected match is under it again; closing sends it home. It floats over the terminal and never moves or resizes it, and its rows start at the first row below the exception strip where that floats in the same corner. Find next and Find previous are actions too (`client.search.next`, `client.search.previous`, no default keys, in Commands): they step an open bar wherever the keyboard is, and bring a closed one back on the pane's last searched text without focusing it, so a search's marks are never on screen without the bar that explains and ends them. While the field holds the keyboard, the terminal's cursor is the hollow outline of a pane without it.
- **Single pane:** a tab with one pane, not zoomed, draws it edge to edge under the toolbar with no card, header, border or margin. Its exception strip floats at the pane's top-right corner. Only Pane headers → Always gives it a card and a header.
- **Pane density:** Settings → Interface offers Compact and Comfortable (default). Compact uses server-defined placements without outer borders, shadows, rounded corners, gutters or outer margins, and without headers unless Pane headers says otherwise; terminal padding stays. Each split boundary has one permanent straight 1 pt separator, with no border around individual panes. Divider hit areas remain over the boundaries, a pane with no header floats its exception strip at its top-right corner, and pane menus retain a square target outline. Focus is shown by the terminal cursor, not a pane border. Per-pane activity words and progress bars live in the header, so they show only where one does; tab activity remains.
- **Pane headers:** Settings → Interface → Pane headers offers Auto (default), Always, On hover and Hidden. Auto follows the density: a header row on the cards of a split or zoomed tab in Comfortable, none in Compact, none on a single pane. Always puts the row on every pane in either density, a single one included, which then is a card. On hover draws no row; resting the pointer for 90 ms in the top 36 pt of a pane floats the header over the terminal's top edge, on `POPOVER` with a hairline under it, and it leaves 220 ms after the pointer does. Hidden draws none. A floating header never moves or resizes the terminal under it, takes no presses until it shows (a pass through the band or a press in it goes to the terminal), and stays away while that pane's search field is open. Reveal pane headers (Commands, `client.pane_headers.toggle`, no default key) floats the header on every pane without a row until it is run again; it is not saved. The header is 30 pt: the pane's name (14 pt from the edge), a `Zoomed` chip (18 pt, keycap fill) while the pane fills its tab, the activity word, then at the trailing end the exception strip, the progress bar and four buttons: Split right, Split down, Zoom (Restore while zoomed) and Close. Buttons are 24 pt targets with 14 pt icons, 8 pt from the edge so a hover fill stays clear of the card's 12 pt corner, `MUTED` at rest (70% on panes without focus) and `INK` under the pointer on a 9% white rounded fill; Close's fill is `DANGER` at 22%. They act on their own pane, focused or not, never keep focus, and show their shortcut in the tooltip. An action that cannot run keeps its place at 35% opacity with the reason as its tooltip: Zoom, on the only pane of a tab. The pane menu's Zoom pane row and Commands' follow the same rule. Close opens the confirmation that names the pane, tab and host. Under 200 pt wide a header keeps Zoom and Close only.
- **Pane cards:** in Comfortable density, splits, and a zoomed pane, are server-defined placements as rounded cards (12 pt radius) with, where Pane headers puts one, a 30 pt header (pane name, its program's activity word, when needed its exception strip, and the pane's buttons), 8 pt gutters and 10 pt outer margin on the ground; their border separates them from the same-coloured ground. Terminal content has uniform four-sided padding in every pane (including below a split card's header), set in Settings → Terminal → Pane padding (0–32 pt, default 8 pt); zero removes content padding but keeps card borders; a terminal background other than `CARD` fills the card's body inside its border, below the header, with the card's bottom corners (and its top corners where there is no header row). Divider drags preview immediately and send a ratio clamped to 0.1–0.9. The header's word is the tab's word for that pane alone (trouble and progress; Done and Bell stay with the tab), follows **Show activity in tabs**, carries the program's message as its tooltip, and stays whole while the name truncates. A pane whose label is still its terminal's default (`shell`, the last word of its flavor) shows its program's terminal title while that program is in the foreground, as a "Shell" tab does; a renamed pane keeps its name, and a pane renamed to exactly `shell` counts as unrenamed. The title is display only: the server label is never changed, and Rename starts from it.
- **Sidebar:** optional; it opens at launch as it was left, at its saved width. Default 236 pt wide (200–360 pt, drag the edge to resize, double-click to reset). Host rows are 28 pt, session rows 32 pt, groups separated by 12 pt. A session row counts its tabs at the right edge only above one tab; a lone tab is what a session has, so it gets no number. With the Sidebar tab position, a session's row becomes a 24 pt muted label and its tabs follow as 32 pt rows indented 12 pt, each with the toolbar pill's icon, label and activity word; the active tab gets the pill's fill and hairline. A tab row has the pill's interactions: right-click for the tab menu (acting on that row's tab in its own session), double-click to rename, middle-click to close behind the confirmation.
- **Popovers:** session/host menus anchor to the identity; pane and tab menus to the pointer (right-click), and pane menus also to the toolbar; the command menu is centered near the top. Popovers are compact: the switcher 340 pt wide, Commands 460, the Add host list 520, pane, tab, session and host menus 280; 28 pt rows (30 in Commands), 26 pt group headers, a 34 pt search field, 5 pt padding and a 12 pt radius. Popovers clamp to the viewport; long lists scroll under a 10 pt edge fade with directional hints that count hidden rows. The selected row is `SELECTION`, and the selection follows the pointer, so exactly one row is lit. The Downloads popover is 440 pt wide, under the chip that opened it (at the toolbar's right end when opened from Commands): a row per transfer of this launch (name cut in the middle by width, so the extension stays, with the resolved remote path as its tooltip, host and state, and the buttons that state allows: Cancel while running; Show in folder once saved, which is the only action a finished row has, since a file's name and content cannot say which program a desktop would run and the default program for a type is not Rex's to vet). A row ends with its shortcut and then a 14 pt column for the chevron of rows that open a dialog or another list; the column is kept on every row, so hints end on one line. A popover never opens another popover from its rows: the switcher's highlighted session row trades its detail for pencil and × buttons, and renaming turns the row itself into a field (accent outline) until Enter or Esc.
- **Menus** are grouped: a 1 pt hairline (9 pt with its margins) separates one group of rows from the next, and a filtered list is flat, with no hairlines. The pane menu's groups are clipboard (Copy, Paste, Select all), layout (Split right, left, down and up, then Zoom pane), the pane (Rename pane…, Copy pane ID, Download file…), its terminal (Clear terminal, Reset terminal, Reconnect terminal) and Close pane…. A row that cannot run now stays in its place in `MUTED` (Copy with nothing selected; Paste, Clear and Reset on a terminal that is not live; Zoom pane on the only pane of a tab), and a menu opens on its first row that can. The rows that end something (Close pane…; Close other tabs… and Close tab…; Close session…; Remove host…) are the last group of their menu, after a hairline, with their labels in `DANGER`; an unavailable one is `MUTED` like any other. On a destructive row the selection tints in `DANGER` and the label turns `INK`.
- **Commands** groups every command by what it acts on, in this order: Session, Tab, Pane, Host, Server actions (only when the host offers any), View and App. A heading names what is on screen ("Tab · dev", "Host · workstation"): the group's word is in small capitals and the name beside it keeps the case it was given, in 11 pt medium `MUTED`, as a host's name does in the switcher's headings; the Pane group is left out when there is no pane, and a command that cannot run now stays in place, disabled. Within a group the order is create and navigate first and the rows that end something (Close…, Remove…) last, after a hairline and in `DANGER` as in a menu. The Pane group lists the pane menu's rows in the menu's order, with hairlines between the same groups, and adds what acts on the focused pane: Search terminal…, Find next and Find previous after the clipboard rows, Split best fit (right of a pane wider than tall, otherwise below) with the other splits, the focus moves, which are disabled in a tab with one pane, and Close pane or tab… beside Close pane…; Download file… keeps its place in the pane's own group. The App group holds Settings…, Downloads (the popover of this launch's transfers), the update, About and Help rows, and Close app. Typing replaces the headings and hairlines with one list under "Commands", best match first (the command named exactly, then a label that starts with the query, then one whose words do, then one that contains it, then a match in the group's name or the command's other names), followed by the matching sessions and tabs under their own headings. Commands shows about twenty rows and scrolls to the rest; its hint names the groups whose heading is still below ("More below: Host · View · App"), never one whose heading is already on screen; when only the rest of such a group is left it says so ("More App commands below"). A row's hint is its action's effective binding, drawn as keycaps, a host's own actions included; a row without a binding shows none, or a few words where they help (Close app: "Programs keep running"). Every registered action has a row, or a reason in `commands.rs` for having none (it needs an argument Commands cannot ask for).
- **Add host list:** each of its groups (Rex servers, Tailnet, Offline) has an icon before its label. A machine's row is columns that line up down the list: its name, which stays whole and is cut only past the room the other columns need; what the machine calls itself, when that differs, which fades out first; what the check found, ending at one x and cut with an ellipsis (its tooltip has the whole text), trouble such as "Rex check failed" in `WARNING` and first; its system in a 52 pt column; and the chevron. A machine that is already added has an "Added" chip in a column of its own, kept only while the list has one, with the saved hosts' names as its tooltip, and no check mark before its name. Rows under Offline don't repeat the word.
- **Dialogs** (forms, confirmation) are centered over a dark scrim and sized to their content within the viewport. The Download dialog is one of them: a field for the file on the host, the folder it is saved in with **Change**, and errors before any bytes in `DANGER` (Rex's own words as they came; the client's own as sentences). Text with no break opportunity, such as a 255-byte name, wraps inside the word and is cut with an ellipsis after a few lines, never past the dialog's edge; a host whose Rex is too old says so in `WARNING` and offers only **Close**; a large file or low space asks in the dialog with **Cancel** focused (a plain button with the focus ring, as **Keep running** is) and **Download** tinted `WARNING` like the close confirmation's danger button, never the accent gradient: the question says what a yes means ("build.img is 3.2 GB. ~/Downloads has 41 GB free.", or for low space "…has 400 MB free, so saving it leaves about 100 MB."). Folders in the dialog, the popover and notices are written with `~` for the home folder and, past about 36 characters, cut in the middle by whole folders (`~/…/reports/final`); the full path is the tooltip and accessible name. **Settings** is a larger dialog (816×680, clamped to 92% of the viewport's width and to what is left under the toolbar with 12 pt clear at both ends, so the toolbar stays whole above it at every window size and interface zoom; the same size on every section) with a 204 pt section list on the left, in gapped groups, and the section's page on the right. Forms and confirmations opened from Settings return to it. A form's secondary action sits at the left of its button row, apart from Cancel and the primary button: Rename tab offers **Use default title** there, only for a tab the user named.
- **Settings navigation:** Search Settings sits above the sidebar, aligned with the page header. The section order is Interface; Terminal, Shortcuts, Integrations, Notifications, Remote Hosts; Updates, About, with gaps between those groups. Each row has an authored 20 pt glyph in a 22 pt tile, accented for the current section. Typing on the section list starts a search; Up/Down selects a result, Enter opens it, and Escape clears the search before closing. Results replace the section list and name the containing page; a setting result scrolls into view and is marked for 2.4 seconds with `SELECTION` behind its content, its helper in `INK` while marked. Back/Forward beside the page title are disabled at history's ends; Alt+Left/Right and mouse Back/Forward use the same dialog-local history and restore page scroll. Opening Settings anew clears its search and history. Shortcuts retains its separate pinned filter and its first Escape clears that filter. Forms and popups stay outside this page history.
- **Settings pages** are built only from the blocks in `src/app/settings_kit.rs`, so every page has one rhythm:
  - A page is sections 22 pt apart. A section is a 13 pt medium heading in `INK` (no small caps; those stay in popups), one or more cards 8 pt apart, and where a group needs explaining a footnote under them (11.5 pt `MUTED`; paths and commands in the mono face). Headings and footnotes sit 12 pt in, on the cards' text edge, and the page title lines up with them.
  - A card is 4% white over the popover with a 12 pt radius and no border or shadow. It draws a 1 pt hairline (6% white, inset 12 pt each side) between every pair of rows itself; a page never places a divider.
  - A row is 40 pt, or 48 pt with a helper: a 13 pt label, at most one helper sentence under it (11.5 pt `MUTED`; longer explanation goes in the section's footnote), and its control in the trailing slot, so every control ends 12 pt from the card's edge. Hard-coded shortcut hints are not written into helpers.
  - Controls are 26 pt tall (segmented controls 28 pt): a switch; a segmented control for two or three choices, each segment 120 pt wide so neighbouring rows line up on both edges, with a leading 15 pt glyph where a picture says it faster (pane density, tab position); a stepper with its value in a fixed 52 pt slot; a popup button (the current value and a 20 pt round badge with an up-and-down chevron) for a value picked from a list; pill buttons; and read-outs: plain `MUTED` text, or a state chip. A state chip is 20 pt tall with a 6 pt radius and 11 pt medium text, a rounded rectangle so it is never taken for a button: a check and `INK` on 7% white for in place, a hairline outline and `MUTED` for absent, `WARNING` on a 12% `WARNING` fill for a state that needs the user. A row that opens a form or a page of its own is a disclosure row: the whole row is the button, with its current value and a chevron at the end.
  - A popup button's list opens over Settings, which stays in place and inert under it, with its trailing edge on the control's and 4 pt below it (above when there is more room there). It has no title, checks the current value and keeps the check's column on every row. Escape, a press outside or a choice returns to Settings with focus back on the control. The chrome palette, pane headers and notice position use the short list; the terminal theme list keeps its search field.
  - Integrations lists each agent on one 40 pt row: its mark at 16 pt in `MUTED`, its name in a 104 pt column, a state chip (Installed, Update available, Not installed, Not found, Conflict, Unreadable) and the buttons that state allows. A state that is trouble says why beside its chip; an agent that isn't on this machine has a `MUTED` name and its reason in the chip's tooltip. Check again and Set up all detected… sit under the card, ending where the rows' buttons do, the primary last. A skill several agents share is explained once, in a footnote with its directory, never per row.
  - About opens with the one centred block in Settings, the app's identity: the 64 pt icon, "Rex Linux" in 15 pt medium, then 12 pt lines for the version (`INK`), how it was installed and, once the active host's server has answered, `Rex Server <version>` (`MUTED`), over the two copy buttons and a one-sentence caption. A fact a server did not give is written as not reported, never guessed and never left blank. Cards follow as on any page, and the whole page fits the dialog at its full height without scrolling; in a window too short for that height, or at an interface zoom that leaves less room, it scrolls as every page does.
  - The page scrolls under its header with a 16 pt fade at whichever edge hides content and a 4 pt thumb while there is more than fits. Unavailable controls are dimmed, never hidden.
- **Shortcuts:** a searchable reference and row recorder for supported actions, including unbound ones, plus bound aliases and the active host's offered server actions. Press a binding to record its replacement; a valid unbound row offers **Record shortcut**. References without valid arguments remain read-only. The recorder holds keyboard focus, ignores IME composition, saves with Enter or Save, cancels with Escape, Cancel or a press outside, and removes the old key with Remove or empty Backspace. Conflicts are warned about before saving. Recordings are an app-owned layer in workspace.json above shortcuts.json; the user file is never rewritten. Replacements keep their mode and conditional arguments. The configuration menu beside the filter copies the file path or a lossless workspace.json fragment, and Reset all asks first, defaulting to Keep shortcuts. A pinned **Filter shortcuts…** field searches action names, categories and keys (`ctrl+k`, or `ctrl+b>c` for a sequence); Escape clears it, then closes Settings. Rows follow registry and argument order, with alternates stacked at the right in try order. Directional actions have a row per direction, so each is searchable. Labels and keycaps use the existing Settings rows and hint tokens; a literal `+` reads `Plus`. Non-default sources, named modes, shared or taken keys and removed defaults are helper text; numpad twins fold only within the same source and mode. Key results retain priority order within each mode, without implying that a mode's keys apply outside it. Pointer Back and Forward remain words, not keycaps. Problems remain below the actions; Files has labelled, selectable one-line paths, middle-truncated with a full tooltip and a Not created chip for a missing server config. No new navigation shell. A pending sequence adds one quiet toolbar chip (`Ctrl B …`, at most 170 pt with a full tooltip); Escape cancels. No timeout, pulsing or terminal animation.
- **Radii:** kit small 8, medium 10; chips 10; cards and popovers 12.
- **Icons:** authored strokes on a 20×20 view box, 1.5 stroke, round caps and joins, `currentColor`. Hosts show their kind (a monitor for this machine's Unix socket, a server for a remote endpoint) in the identity chip, sidebar headers and switcher groups; the Add host list's groups show a server, a mesh of three nodes (Tailnet) and a moon (Offline); tabs carry their program's icon at 15 pt (Claude Code, as `claude` or `claude-code`; Codex, OpenCode, Pi, whose mark OMP shares; Vim, Git, Cargo, SSH), or `>_` for shells and anything else. Pi and OpenCode use solid marks after their own logos, since outlines of them are unrecognisable at that size; the Commands button is ⌘. Magnifying glasses mark search fields only.
- **Elevation:** the working canvas is flat. Popovers and dialogs get a frosted fill, a lit gradient rim and a deep soft shadow.
- **Interface zoom:** 70–150% in 10% steps. Zoom above 100% is limited to preserve a 640×480 layout floor where the viewport allows; terminal font size is independent. `Ctrl +`, `Ctrl −` and `Ctrl 0` stay interface zoom; the terminal font size actions (Increase, Decrease and Reset terminal font size, in Commands) step the font one point within 8–48 pt or return it to the default, and have no default keys, so no chord is taken from terminal programs until the user binds one. Either change says its result in one notice that replaces the last ("Terminal font 16 pt", with "· maximum", "· minimum" or "· default" when it applies); a step at a limit changes nothing and says so.

## Interaction

- Workspace defaults are listed in the README; every binding is removable or replaceable. The active host’s effective map drives dispatch, Settings and Commands; unbound keys reach the terminal through `client.key`. Only popup editing/navigation and Escape cancelling a sequence remain reserved. Every shortcut hint comes from the effective keymap through one formatter (`keycaps.rs`), in one spelling (`Ctrl Shift D`; `Ctrl B, C` for a sequence): menu rows, Commands, the switcher, the sidebar's Find a session chip, toolbar tooltips and the empty workspace's text. No hint is written out by hand, so a rebind shows everywhere at once. In lists and the sidebar a hint is drawn as keycaps: one 17 pt chip a key (7% white, 10.5 pt text halfway from `MUTED` to `INK`, which meets 4.5:1 on its chip in every palette; `INK` on a 12% chip in the selected row), the chords of a sequence joined by a muted "then". A tooltip names its control and then the keys (`New tab · Ctrl Shift T`). Commands details use the highest effective binding for their action and args (among an action's default bindings that is the main block's key, not the numpad's); unbound actions have no keyboard hint, in a row or a tooltip, while mouse Back/Forward show literal pointer hints as plain text until they are given a key. The reserved popup keys are keycaps too (`Esc` in a search field, `Enter` in an inline rename). Ctrl Tab and Ctrl Shift Tab traverse connected hosts, sessions and cached tabs in sidebar order, wrapping; an uncached session is one stop. Cross-session cycling settles for 150 ms before attachment, without animating terminal content. Mouse Back and Forward revisit window-local history and never reach terminal mouse reporting or navigate behind a panel. Commands exposes the same named navigation actions; Ctrl PageUp and PageDown remain server-controlled within the current session.
- SSH setup is separate from attachment: a missing default server offers **Start personal server…**, then a dialog names the host, full endpoint, exact command and effects. **Not now** is the default; only **Start personal server** authorizes a one-time attempt. Busy setup disables repeated starts, errors remain in the dialog, and closing a busy dialog does not claim to cancel the remote start. No automatic future start or installer prompt approval is implied.
- Opening a form or search focuses its first field; close confirmation focuses **Keep running**. Tab and Shift-Tab cycle fields and actions in panels; Enter and Space activate; Escape backs out and restores the previously focused pane. Tab, Space, Return, Escape and Menu never move focus away from the terminal unless a panel is open.
- Right-click captures the specific pane under the pointer; its menu names tab and pane and keeps a target outline through rename and close. A target that disappears dismisses the menu with a notice instead of retargeting.
- Size ownership is automatic and has no control of its own: the window claims the panes on screen when it comes forward, and typing or pasting in a pane claims that pane. A pane another client has claimed since is left alone until then: it draws at that client's size and never sends a resize. A reconnecting terminal shows an exception strip with **Retry**.
- A transport failure marks affected panes input-paused, keeps their output, and never queues or replays input. Notices are toasts: errors are sticky, information leaves after about 6 seconds, and at most three notices are retained. A verified release update adds one non-blocking update toast (accent dot, channel-specific upgrade summary, **What's new**, **Updates…** and dismiss-for-this-version) and a **Settings → Updates** section with **Copy command** and opt-out; background update check failures are silent and never produce a toast.
- Remote control is a per-host switch in Settings → Remote Hosts, off by default, with a Commands toggle for the host on screen. The client label is editable there too. No healthy-state badge: each performed request gets one six-second notice naming host, requester and action. Off explains itself once per host per launch; other refusals are quiet. Requests never raise the window or open a dialog.
- Focus cues: the focused terminal draws the cursor shape its program asked for (a filled block unless it chose a bar or underline), other panes, and every pane while the window has no focus, a hollow outline block, and in Comfortable density a pane card has an accent outline when focused and no panel is open. Cursor blink requests draw steadily, like the rest of terminal content.
- Links open only on Ctrl+click (press and release on the same link), never on a plain click, so selecting text and clicking into programs stay unchanged. Holding Ctrl over a link underlines it in its own text colour, shows the hand pointer and gives it a tooltip with its target URL (never its displayed text).

## Do and don't

- Do keep the toolbar single-row and the terminal canvas dominant.
- Do keep chrome tokens in `theme.rs` rather than hard-coding colours in views.
- Do derive overflow cues and hidden-row counts from measured content.
- Don't recolour terminal output to match the chrome, or animate terminal content.
- Don't let selecting, copying or navigating claim size ownership.
- Don't add status dots, "Connected" labels, terminal size readouts or keyboard-hint footers.
- Don't show illustrative sessions, layouts or captures as shipped runtime state.
