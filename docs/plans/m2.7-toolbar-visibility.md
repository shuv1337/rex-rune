# M2.7 — focused toolbar visibility slice

Implemented on `fd55bca` (Settings search/history #62), recovering the toolbar behavior and focused tests from preserved W2 `cc8bdad`. This is **not all of M2.7** in [the parity roadmap](../parity-2026-11/GAP-REPORT.md). Checked 2026-11-11 (PST).

## Scope

- Settings → Interface → Toolbar visibility, using the existing page, section/card/select-row kit and automatic Settings search index. No new page or navigation shell.
- `interface.toolbar`: `always` (default), `on_hover`, `hidden`. Old files and unknown future string values use Always show. Each mode survives save/load.
- Always show retains the old 52 pt working row, including its spacing, Downloads chip, pending-sequence slot, tabs and sidebar button.
- Show on hover and Hidden give that row back to the terminal area. Comfortable split cards/sidebar retain a top outer margin; full-bleed and Compact terminals can use the entire height.
- Show on hover watches the top 8 pt from behind the panes and toolbar, preserving left-clicks and context menus, reveals after 80 ms, and leaves 320 ms after the pointer does. Only the floating toolbar animates; revealing/hiding it does not change pane/grid geometry, terminal rows, content transforms or the server's split layout.
- `client.toolbar.toggle`: **Reveal toolbar**, default `Ctrl Alt Shift T`, in Commands and the current searchable Shortcuts page. It temporarily pins the floating bar; running it again puts it away. Always show disables the Commands row. `Remote::Never`; the existing pinned remote allowed set is unchanged. Its shortcut is removable/rebindable, and the setting's recovery note reads the effective keymap.
- Settings (`Ctrl ,`) and Commands (`Ctrl Shift P`, including Close app) remain available without the bar. Window-manager Move/Close remain available independently. Escape closes a panel before workspace shortcuts. Reveal restores the normal drag area and Close button.
- Receiving-download and pending-sequence chips float while the toolbar is absent, retaining the existing narrow-window priority. No invisible toolbar/buttons remain over the terminal. Notices stay at their configured corner and move below a revealed bar. The download list remains reachable from its chip or Commands.
- Settings reserves only permanent toolbar height, so transient hover cannot move the modal. A concrete regression exposed by the longer Interface page was fixed: popup anchoring now uses Rune's scroll-aware `window_layout`, rather than the unscrolled row position. Existing picker tests still cover zoom and returning focus; scrolled notice/download controls are exercised too.
- Revealing schedules the existing active-tab scroll again, including after navigation while the tab strip was absent.

No Left/Right rail, font/theme/tab redesign, pane controls/cues, focus-follows-mouse, animation preference, layout balancing, fork harvesting, recorder work, Shortcut-page migration, protocol changes, release/version/tag or PR work.
