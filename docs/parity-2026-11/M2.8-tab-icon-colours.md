## Behavior and boundary

Interface → Sidebar and tabs adds **Use colour for tab icons**, an existing-kit
anchored choice: **Always / Active pane / Active tab / Never**. The persisted
enum is `interface.tab_icon_color`, with snake-case values `always`,
`active_pane`, `active_tab`, `never`. New, old and partial files default to
Never; unknown strings deserialize as Never. No existing setting is moved.

- **Always:** every displayed program glyph is tinted.
- **Active pane:** only the first representative glyph of the tab on screen.
- **Active tab:** all displayed glyphs in the tab on screen.
- **Never:** the exact #73 active/inactive monochrome glyph ink.
- On screen means the current host, its selected session and that session's
  active window, not a matching window ID on another host/session, and not a
  background session's own active-window selection.
- #73's focused-first resolution, deciding-status-app/foreground fallback,
  deduplication by glyph, stable server pane order, count cap and tooltip source
  remain unchanged. The first glyph represents the focused pane, including the
  first-block fallback for missing/invalid focus and the terminal fallback for
  empty or unknown metadata. There is no severity sorting or duplicate tint.
- Only the existing glyph's colour parameter changes. No badge, shell tile,
  asset, program mapping, action, permission, probe, process read, fetch or
  server request is introduced. Labels, selection shapes, activity/progress,
  terminal content and geometry remain independent. Colour is not the sole
  selection or program-identity cue.
- The two inert **Active sample / Inactive sample** rows use the same resolver
  and renderer as toolbar/sidebar tabs. They respond to mode and count, fit the
  existing scrolling Settings page at 640×480, and send no input. Count 0
  creates no glyphs; its helper explicitly says none are shown while **Show tab
  icons** is 0. The count setting's default, helper, tooltip and semantics stay.
- Colour changes save locally; unlike count/fill, they do not request a
  selected-tab reveal because no geometry changes.

The policy and finite per-glyph hue table were informed by read-only
`cc8bdad:src/app/tab_icons.rs` (`tint`, `IconLook::in_color`) and
`cc8bdad:src/settings.rs` (`TabIconColor`). This is a narrow adaptation on
current code, not a prototype import. In particular it excludes its badges,
tiles, ShellIconTheme and theme-derived colours. Shell/unknown is simply the
existing prompt glyph in green. **Shell-theme styling remains deferred**;
there is no bundled-theme import or licensing claim.

selected surfaces (for example Git about 1.71:1 on selected Gruvbox sidebar in
the headless capture). The finite table was lightened, without changing theme
tokens or adding runtime contrast machinery:

| Git | `#ffcad1` |
| Cargo | `#efd0b6` |
| SSH | `#f5dc8c` |
| Shell / unknown | `#a1edac` |

The test checks all nine glyphs against all four supported palettes, toolbar,
sidebar and preview surfaces, plain/hover/selected: **324 contrast checks,
minimum 3.12:1**, Cargo on selected Gruvbox preview. It uses linear-light
white-over compositing (the brighter headless path), not an sRGB approximation.
This is the graphic 3:1 threshold; it does not claim the glyphs are body text.
The existing text tokens are not changed. Native X11 captures have darker
translucent fills than the headless renderer; both were inspected.

**120 individual real-font captures**, Inter / IBM Plex Mono, at 1024×700 and
640×480: all four modes × four palettes × toolbar/sidebar/preview, plus Always
hover surfaces and the remaining authored glyphs (Codex/OpenCode/Pi/SSH and
fallback). Inspection sheets cover every mode/palette at both sizes.
Active/inactive glyphs and unchanged terminal red are visible. At minimum
width the toolbar can expose only the trailing part of a five-icon tab; that is
the existing #72/#73 overflow/reveal constraint, not changed by colour.
The sidebar and preview demonstrate the complete row at that size.

Rerendered the unchanged #73 `tab_icons_draw` fixture at both sizes:
**30 complete non-Settings frames are pixel-identical** to saved #73 fixtures,
covering counts 0/1/5, toolbar, fill, sidebar, sidebar status and active status.
