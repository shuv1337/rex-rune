# M2.7 — header-only fading

Implemented from released `20e4bbf99b31a8f8edeaeb79ea54268ba746209c` (v0.7.3).
Validated locally 2026-11-11 (PST). This is a standalone, partial M2.7 slice, not the complete roadmap item or preserved Wave 2.

## Shipped scope

Two existing-kit switches under **Settings → Interface → Panes**, both default-off:

- **Fade inactive pane headers**: `interface.fade_inactive_pane_headers`. Applies to panes other than the session's focused pane.
- **Fade headers in inactive windows**: `interface.fade_pane_headers_in_inactive_window`. Applies to every pane while the native window is unfocused.

Either condition applies the same fade once; they do not multiply together. Missing keys preserve current visuals. Both persist immediately and are indexed by their actual visible Settings labels, with the existing search/history machinery. No new page, action, shortcut or remote surface.

Only the header **name and available button icons' resting colour alpha** change. There is no opacity on the header, actions cluster or card. Hover restores the name's original colour and an available icon's existing INK colour; hover/press fills, hit targets and the button's preserve-focus behavior stay intact. Unavailable Zoom retains its original 35% opacity and cannot run. The Zoomed chip, activity words, progress, exception strips (including Retry) and every terminal descendant are unchanged by either preference.

Placement still belongs exclusively to Pane headers Auto/Always/On hover/Hidden and temporary Reveal pane headers. No row is introduced, no overlay resizes the terminal, and no layout/ownership/input command is sent by a preference change. Existing density, pane zoom and interface zoom behavior remain. Native focus-in **still claims visible panes under the existing policy**, independent of these switches; native focus loss still hollows the cursor and ends an in-progress selection. Fading does not suppress or add those behaviors.

No changes to the #68 inert outline overlay or `on_layout_tx` feedback fix, #67 font metrics/isolation, #66 cursor/selection/PRIMARY, toolbar visibility, recorder, generated titles, Downloads or remote consent. No vendor/dependency/lock changes.

## Visual choice and contrast

Use **0.85** as a gentle extra colour-alpha multiplier, not the preserved prototype's 0.45. It keeps the existing distinction between a quiet, available icon and the much dimmer unavailable icon. A previously unfocused icon's 0.7 resting alpha becomes 0.595; an unavailable icon is not multiplied again. Both switches off retain all original colours, including hover.

Nominal contrast was inspected using Rune's linear-light colours and sRGB render target, not an incorrect sRGB-channel blend. The evidence file `contrast.json` records all four palettes. On default Midnight, the faded inactive name is **6.25:1** on CARD and **6.19:1** on POPOVER; the faded inactive available icon is **4.68:1 / 4.63:1** respectively. The old 0.45 would leave the Midnight name only about 3.8:1.

**Limit:** this is not an AA small-text claim for every optional palette. Faded muted names on Rosé Pine Moon are about 4.28:1 on CARD / 3.94:1 on POPOVER; Gruvbox Dark is 4.66:1 / 3.70:1. Their existing floating muted names are already approximately 4.46:1 / 4.17:1 before fading. The weakest faded available icon is about 2.89:1 on Gruvbox's floating surface; hover returns its full-strength INK affordance. No theme tokens or palette behavior were changed in this slice. The preference remains off by default; do not describe it as a contrast/accessibility improvement.

Real-font Midnight captures were run separately at **1024×700** and **640×480**, then inspected: both switch labels and helpers remain whole, the controls fit, dimming is restrained, and Error/progress/Retry remain conspicuous. The narrow exception strip retains the existing Retry-only presentation. At both sizes, a pixel comparison of default versus inactive-pane fading changes exactly 506 pixels, all within the inactive header's name/icons band (normal bounding box 530,62–997,72; minimum 338,62–613,72). Neither activity/progress/exception pixels nor terminal pixels change.

### Real native acceptance

`REX_BIN=<built release binary> python3 scripts/header-fading-x11.py` passed on private Rex API 13, Xvfb and openbox at 1024×700. The script clears inherited Rex/display/XDG settings and creates disposable state; no personal server, display or clipboard is used. A private xmessage window receives focus without obscuring Rex.

With the inactive-window switch both on and off, real X11 focus out/in changes the header pixels only when enabled and restores the original header on return. The cursor-hidden terminal body is pixel-identical throughout. Server columns, rows, owner and focused block stay the same. Actual-label Settings search toggles and saves the switch. A raw PTY recorder receives exactly the one deliberate `x` byte at the end: no leaked Settings keys or focus-event input. This checks the same-owner focus path; it does not claim that native focus-in stops reclaiming from another client.

## Deferrals and limits

Preserved `eeb7e870df85a95c87261e9deaee0e52825caeaa:docs/parity-2026-11/M2.7-focus.md` documents the held-secondary-button capture blocker: the application cannot see a held right-click before release while delayed hover can fire. None of its characterization probes, polling, weaker focus behavior or Rune changes are imported here.

Native Wayland/compositor, IME, screen-reader, fractional-DPI and multi-client native-focus acceptance were not run. Existing tests cover unaffected features but are not claims of new live validation. Optional-palette contrast limits are stated above; real-font captures here use Midnight. Themes/licensing, tab icons/program fills, animation settings, tray, move-to-new-tab, autobalance and releases remain outside scope. Parent owns PR #70 and final CI/merge; no version bump, tag or release work is included.
