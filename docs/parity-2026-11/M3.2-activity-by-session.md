# M3.2 — Activity by session (partial)

Implemented and checked on 2026-11-12 (PST), branch
`parity/activity-by-session`, against the fetched `origin/master` recorded in
`base-commit.txt` under the evidence root.

## Implemented

The Activity list has a second ordering of `Workspace::activity_tabs`, not a
second inventory, status pass or subscription. **By priority** retains its
original groups, entries and presentation. **By session** groups the same filtered
rows under `session · host`, using the existing tab-description naming rules.
Both chosen names keep their case, with the shared heading's truncation tooltip.
Group identity is host/session, not the displayed string: even identical names
on identical host labels stay separate.

Sessions sort by their most pressing **remaining filtered row** (Needs you,
Error, unseen Done, Working), then saved-host order and server-session order.
Within a session, priority comes first and server-tab order breaks ties. Empty
groups are not produced. Filtering still searches the original title, session,
host, state word and priority-group word before changing presentation.

The by-session row omits its redundant place line: the heading already supplies
both parts. Its title is vertically centred in the same 44 pt row; the original
program glyph, state colour, right-aligned state/time and selection outline stay.
There is no new count, collapse state, per-host grouping or animation.

### Actions, keyboard and preference

- Existing `client.activity` takes an optional `view` argument (`priority` or
  `session`). Invalid values and extra arguments are refused before dispatch.
- Commands retains **Show activity…** (remembered view) and adds **Show activity
  by priority…** and **Show activity by session…**. These are three rows of one
  action, not three action names. The two explicit rows also remember their view.
- Settings → Shortcuts derives the optional enum choices from the action schema
  and retains its no-argument row. All three are recordable, searchable and
  unbound by default, and show only their own effective bindings. There is no new
  Settings preference row. The pinned remote allowed set is unchanged;
  `client.activity` remains `Remote::Never`.
- **Tab / Shift-Tab while the Activity filter has focus** switches the two views.
  Tab was already consumed by the single-field list; it is not printable filter
  text, and this takes no default shortcut from terminal programs. Filter text,
  field focus and selected `(host, session, tab)` survive; the row follows the
  identity, not its old index. Other popup Tab behaviour is unchanged.
- `workspace.json` remembers `activity_view: "session"`. Missing/unknown values
  use Priority; Priority is omitted when saved. Plain command and toolbar chip
  open the remembered view. The chip still chooses the first row not in front,
  now in the selected ordering.

Opening, switching, filtering and browsing are local; no host/terminal commands,
read receipts, notification closures or Done/Bell changes. Choosing a row retains
the existing notification-navigation path and normal acknowledged-view receipts.
Coverage and popup-owned minute refresh are shared and unchanged.
