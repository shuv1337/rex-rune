# M3.2 — Activity list (partial)

## Shipped

`client.activity` opens **Show activity…** from Commands and has a recordable row
on Settings → Shortcuts. It is `Remote::Never`; the existing eight-action remote
allowed set is unchanged. The shared list popup displays one row per qualifying
tab, filters by the pill's title, session label and saved host label, and navigates
through the notification click's path (`show_noted_tab` → `select_window`), without its
request to raise the window. A captured row whose host/tab is gone says
“That tab is no longer available.” rather than selecting a replacement.

Opening, filtering, rendering and dismissing are local reads. They neither query
Rex nor mark tabs read. In particular they do not change Done/Bell latches or close
notifications. Choosing a row uses existing navigation (including its visibility
and Navigate commands); the normal acknowledged-view activity tracking clears
latches. No dependency, setting, server subscription or status query was added.

## Decisions

- **Default key:** unbound. `Ctrl .` does not occur in the shipped defaults, but it
  may be useful to terminal applications, particularly extended-keyboard clients.
  Avoid taking it on a release-adjacent slice. The normal recorder can assign and
  remove a binding; existing all-action wiring tests cover that path.
- **On-screen tab:** included when Working, Needs you or Error. The list answers
  “what is happening?” rather than just duplicating unread notifications. Done
  still requires the existing unseen latch. Idle and muted tabs are excluded.
- **Groups:** reuse the popup's existing group headings, in Needs you, Error, Done,
  Working order, including while filtered. Stable sorting preserves saved-host,
  server-session and server-window vector order within each group. The Session
  Commands group contains Show activity after Switch session, keeping the latter
  the default selected command.
- **Rows:** reuse the shared selectable row, with its selection tint **and** outline,
  adding the focused program's existing monochrome glyph and a second line for
  `<session> · <host>`. The title uses the pill's existing resolver. Trouble words
  use WARNING, Error DANGER, Done ACCENT, and Working MUTED. No dots or new assets.
  The list's single representative glyph is independent of toolbar icon count.
- **Coverage line:** “Tabs in sessions not opened since connecting may be missing.”
  Once, quietly below the search field, including the empty state. (The parent
  reworded the first draft, “Only received activity is shown. Some tabs may be
  missing.”, to say which tabs.)
- **Live selection:** before an existing host wake replaces its model, capture the
  selected `(HostId, session, window)`; after activity tracking, find that same tab
  in the freshly derived list. If it left, clamp the previous position. No timer,
  polling, duplicate activity model or background work. Filtering deliberately
  starts at the first match, like the other lists.
- **Existing Show activity in tabs setting:** still controls tab words only. It does
  not suppress this explicitly opened list. Mute does suppress a tab here.
- **Bell and OSC 9;4-only progress:** not additional list categories. This slice
  indexes folded OSC 7501 state plus the existing unseen Done latch. Bell latches
  remain untouched by browsing.

## Precisely what can appear (and what can be missing)

The index walks **connected** hosts, their current `HostModel.sessions` in order,
then the windows of each session's cached `HostModel.views` entry. A window needs a
window ID and must not be muted. It qualifies for folded Blocked (with the same
Needs approval / Question / Needs sign-in / Needs input wording as the pill),
Error, Working, or unseen Done (including a Working/Blocked → Idle completion).
A Done record without an unseen latch is not listed.

The existing connection—not this popup—gets layouts from bootstrap/selection and
refreshes cached layouts from live events. Notably an activity/title/process/bell
block event for a known but unplaced session already attempts a read-only layout
refresh, once per connection (`ControlState.viewed`). Thus a never-opened session
**can** appear after a live event successfully places it; it is not limited to
sessions explicitly visited by the user. A failed unplaced-session layout fetch
leaves no rows for that session until another existing navigation/refresh path
obtains it. One such path is the existing sidebar prefetch: with tabs listed in the
sidebar and a host expanded, it places every session's layout and retries failures;
sessions retained from an earlier connection are attached at bootstrap too. Neither
adds activity, only layouts. Unknown/removed sessions, uncached layouts and windows without IDs
cannot appear.

`query_activity` asks once per terminal block **of the selected session**, after
connect and later existing connection processing/selection. It does not query
background sessions merely because their layout is cached. Already-reported
background status from before connecting (or while disconnected) may therefore
be absent until a new live event or a visit to that session. Query failures are
not retried for that block in the same connection. On reconnect, layouts and
activity metadata are cleared and rebuilt by those same paths. Queried Done is
not live news and alone does not create a Done latch. A background tab reporting
only Idle at completion without this client knowing its prior Working/Blocked
state has no completion latch; a live Done report can latch without a prior state. Offline hosts are omitted, not shown as current activity.

Status records are block-keyed within a host; tab latches are host/window-keyed,
as before. Real Rex IDs are unique within a host. Tests deliberately reuse tab,
block and session IDs **across hosts** and check session-qualified navigation,
without inventing a second interpretation for impossible within-host ID reuse.

## Later polish (after 0.7.5)

Three of the review's follow-ups, made on `f807c8f`:

- The filter also matches a row's state word and group, so `error`, `needs` or
  `working` narrow the list.
- Opened from the toolbar chip, the list starts on the first row that is not the tab in
  front. The chip counts tabs other than that one, and the on-screen tab can head the
  Needs you group; opened from Commands or the action the list still starts on its
  first row. If only the tab in front qualifies, it is selected.
- The coverage line names hosts that are not connected ("1 host is not connected. Tabs
  in unopened sessions may be missing."), since their tabs are not listed and "Nothing
  needs you." beside a host that is down read as all clear. It says "not connected"
  rather than "offline" because it also counts hosts still connecting at start-up and
  hosts reconnecting. The shorter "unopened sessions" keeps the line whole in the 460 pt
  popup (the reviewer measured about 345 pt for a twelve-host line).

so the two cannot drift apart. Tests:
