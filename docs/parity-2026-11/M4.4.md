# M4.4 recovery: shortcut recorder

Recovered on `eee66f8`, then rebased onto `fd55bca` (merged Settings navigation
PR #62, including the About section-indexing fix). This is only M4.4, not a
whole-Wave-2 import. The baseline gap report and its historical counts are unchanged.

## Scope and provenance

- Adapted `f6867b6`'s recorder, recorded settings layer, chord capture and tests;
  consulted `cc8bdad`'s Shortcuts refinements. Existing source worktrees/caches
  were read only. Builds use a separate reflinked cache.
- Row recording: click a binding to replace/remove it, or Record shortcut on a
  valid unbound action. Enter/Save commits, Escape/Cancel/outside press cancels,
  Backspace takes back a chord and empty Backspace removes the old binding.
  Sequences contain up to four chords. Plain initial typing is refused.
- The recorder owns keyboard focus, captures global shortcuts instead of running
  them, ignores composition and repeats, and consumes releases. Escape cancels
  even during composition; a late IME commit cannot become a terminal paste while
  Settings remains open. Leaving Settings or its page discards the recorder.
- Existing arguments and named modes survive replacement. Read-only argument
  references remain read-only; valid aliases keep their identity. No new argument
  editor, mode definition UI or unsupported-action implementation is introduced.
- Conflict warnings cover exact keys and overlapping prefixes, only within the
  same mode. They say saving takes priority **where both apply**, not that a
  conditional shortcut erases an unconditional fallback. The `1315556`
  conditional-shadowing and exact-key-search behavior is retained.
- `recorded_shortcuts` is an app-owned workspace.json layer above shortcuts.json.
  Nothing in recording, removal, reset or export writes the user's shortcut file.
  Removals name an action and mode. Default keys can be restored; an argumented
  default keeps its row after removal. File reload preserves the recorded layer;
  declarations reach connected and disconnected hosts.
- The configuration menu copies the shortcuts path, exports recorded changes and
  confirms Reset all with **Keep shortcuts** as the safe default.
  **Export differs deliberately from the preserved implementation:** it is a
  lossless `{"recorded_shortcuts": [...]}` workspace.json fragment, not
  shortcuts.json's less expressive format. This avoids dropping named modes or
  broadening an action-specific removal into a removal of every action on a key.
- Commands offers Change shortcuts… (`client.shortcuts`, Remote::Never) and
  Ctrl Enter to edit a highlighted command with a valid binding target.
- A changed key-filtered row stays reachable and focus returns to it. Four-chord
  readouts truncate inside the recorder with the full spelling in their tooltip
  and accessible name; saved sequence buttons stack steps with “then”, rather
  than overflowing the minimum-size dialog.

The PR #62 Settings shell, history, search registry and kit row indexing are
unchanged. Only the Settings-open hook adds recorder cleanup alongside
`settings_nav.opened()`. PR #57 host modes/aliases and the remote allowed-set
tests remain. No toolbar visibility, fork icon, tray, version, release, vendor,
trust, attachment, server ownership or download-policy changes.
