# M3.4 — optional activity sounds (partial)

Base: `1f5ce5a` (`origin/master`). Verification: 2026-11-12, Pacific Standard Time.
Partial **d5-30 / d5-31** only, not the rest of M3.4.

## Shipped

- **Play sounds**, Settings → Notifications, is **off by default**. Old JSON loads
  with it off; `notifications.play_sounds` is omitted when false. Updating this
  terminal client must not make it start making noise.
- `activity.rs::track_activity` still makes the news/visibility decision.
  `notify_state` applies the existing event-kind and muted-tab decision once,
  then dispatches independent desktop and sound channels. Sound additionally
  requires a live record and one of Needs you, Error or Done. Working, read-back
  records, program messages and terminal bells never request sound.
- The tab in front of a focused window stays quiet. With the window unfocused,
  that tab can notify too. No sound decision marks a tab seen, claims ownership,
  changes terminal content/layout, or sends input or a server request.
- Fixed freedesktop names: Needs you → `dialog-warning`, Error → `dialog-error`,
  Done → `complete`. No sound choices, volume slider or bundled audio.
- Sound is independent of the Desktop notifications switch and D-Bus health.
  The existing per-kind controls remain usable for sound when desktop delivery
  is off (Starts working still belongs only to desktop delivery).
- **Play** explicitly tests Done, even with Play sounds off. It is a Settings
  button, not a new registered action or shortcut. No remote allowed-set change.
- The helper next to the switch reports the last check/attempt: player found,
  no player or theme files found, failed attempt, timeout or worker unavailable.
  It is quiet helper text, not a warning chip/toast. A successful page check does
  not hide the last failed attempt; a successful attempt clears it. The switch
  stays usable when playback is unavailable. No automatic install or retry.

## Process rules and implementation

| Rule | Enforcement |
| --- | --- |
| No work on activity with the switch off | `activity.rs::notify_state` gates before `sound_request`; lazy `Sounds::request` starts no worker for Cancel. No lookup/spawn on disabled events. |
| No discovery/spawn/wait on UI or host loop | `sounds.rs::run` is a dedicated worker; UI requests only touch a small mutex-protected slot and bounded wake channel. Settings draw only reads `sound_health`. Both page-entry paths in `workspace.rs` request one Check. |
| Player order and theme files | `sounds/player.rs::select`: `canberra-gtk-play`, `pw-play`, `paplay`, searched on local PATH. Canberra gets `[-i, fixed-id]`; the others get one absolute `.oga` path under `sounds/freedesktop/stereo` in XDG_DATA_HOME then XDG_DATA_DIRS (standard defaults; relative XDG directories ignored). |
| No shell or remote command data | `Sound::id` is a three-case constant mapping; `Invocation` is made only by `select`. `System::spawn` uses `Command::new(...).args(...)`, null stdin/stdout/stderr and inherited local launch environment. No server/title/message/app text is accepted by the sound API. |
| No chorus or delayed queue | `sounds.rs::Gate` gathers for 100 ms, keeps just the highest severity (Needs you > Error > Done), and admits no further event until one second after that attempt begins. Events while busy/cooling down are dropped, not postponed. Stale gather slots older than a second are discarded. A bounded one-token wake channel is not a command queue. |
| At most one player | One worker owns the child; Gate stays busy through discovery, spawn, polling and reap. Explicit Play while busy is ignored rather than queued. Play supersedes pending event audio and remains Done even if more events arrive. |
| Timeout, kill and reap | `sounds/player.rs::attempt` polls the child, enforces three seconds, calls the child's own `kill` on timeout/shutdown/poll failure, and always `reap`s a spawned child, including non-zero exits. No process-name matching. |
| Exit cleanup, without waiting in the UI | Dropping `Sounds` signals stop and wakes the worker. `app/mod.rs::run` retains a `Shutdown` and calls `finish` after Rune's event loop ends, joining the worker after child kill/reap. Normal exit/re-exec cannot leave a player behind. |
| Failure isolation | Missing, spawn, exit and timeout failures update only the sound helper; no logs per event, toast, notification change, replay or fallback attempt after a failed spawn/play. The next explicit/event attempt discovers afresh. |

A 100 ms gather window deliberately trades a small response delay for choosing
one meaningful sound across nearby host updates. The rest of the one-second
interval is a drop window, not a delayed-play queue. This is client-wide, not per
host or tab. Play bypasses the event cooldown but never overlaps a player.

One existing boundary is preserved: the legacy desktop `finished` rule can call
a Working/Blocked → Done/Idle transition news even when the deciding record is
not live. Sound explicitly rejects those read-backs as required; the desktop
notification/latch rule was not changed in this slice.

## Verification

Evidence: `~/.cache/agent-ws/rex-m34-sounds/`. One checkout-local `target/`, dev/test
debug info disabled for disk space, `TMPDIR=/var/tmp` for tests. All tests use
fake players, independent of installed audio programs. No real audio was played.

### Automated checks

All requested checks passed (exit 0):

- `cargo fmt --all -- --check`: `fmt.log`.
- `TMPDIR=/var/tmp cargo test --locked --all-features`: `tests-final.log`,
  **1,016 passed, 0 failed, 6 ignored** (332 library, 676 UI/binary, 8 integration
  passes; all six ignores pre-existing). Nineteen focused sound tests were added.
- `cargo clippy --locked --all-targets --all-features -- -D warnings`:
  `clippy-final.log`. Existing vendored Rune warnings are unchanged.
- `cargo build --locked --release --bin rex-linux`: `build-final-2.log`.
- Python fixture syntax check and `git diff --check` passed. The mechanical
  Settings detector reported no findings (`design-detect.json`).

The disabled-switch regression was actually made red: temporarily replacing
`config.play_sounds` with `true` in `notify_state` made
`sound_off_never_looks_up_or_spawns_for_any_activity` fail on a non-empty lookup
log (`regression-disabled-gate.log`, exit 101). The guard was restored before the
passing full run; every invoked player in this experiment was still fake.

The first full run found an existing history test's fixed 110-point scroll no
longer put Messages from programs on screen after adding a row. It now checks
that the wheel scrolls, then explicitly scrolls that target into view before
checking exact scroll restoration and pointer navigation. No assertion was
removed or loosened. The existing sound search test now pins both actual hits
and still verifies selecting the page hit rather than marking a row.

With sounds off, the fake records **zero lookups and zero spawns for all activity
states**, and native event acceptance records an empty file. Existing Settings,
terminal geometry/content and remote allowed-set tests pass. No renderer for
other pages changed; historical captures of other pages were not regenerated or
compared pixel-for-pixel.

Focused coverage includes defaults/old JSON/round trip, disabled zero lookups and
spawns, fixed ids with hostile title/message/app strings, visibility/mute/kind
filters, read-back completion, Working and program messages, desktop-off/missing
service independence, failure isolation, severity/cooldown/drop semantics,
explicit Play, cancellation, XDG/PATH selection and exact argument vectors,
missing players/files, spawn/exit failure, timeout and shutdown kill/reap with an
injected clock, and searchable local-only Settings controls at both sizes.

### Private native acceptance

`scripts/activity-sounds-x11.py` creates its own Rex server and reporter programs,
Xvfb/openbox, HOME/XDG, session bus with no activation directories, and private
PATH. All three player names are fake scripts that only append JSON argument
vectors to a file; the resolved paths are checked before every app launch.
There is no path to a real player, even on fallback. Children stop by PID.
Mesa lavapipe is selected by its explicit ICD path so the private XDG data
folders do not hide Vulkan discovery. The fixture closes via the app's own
button, independent of a window manager's Alt-F4 configuration.

The test drives real OSC 7501 needs-you, error and done reports, plus a five-tab
mixed burst. It checks the complete argument log after each stage, no extra or
delayed playback, silence with the preference off, and playback both with desktop
notifications off and with an absent notification service. It also clicks Play
with the switch off (one explicit `complete` invocation, no preference change),
and closes each app normally, exercising the worker shutdown join. Headless
channel assertions, not native traffic interception, verify no server/PTY/ownership
effects.

Final release acceptance passed (`native-final.log`, exit 0), artifacts in
`native-ohtah7jl/`: **9 exact invocations** — one explicit Play with the preference
off, then three individual ids and one highest-priority burst for each desktop
notification mode. `off-event-audio.json` is `[]`; `audio.jsonl` and `result.json`
record the complete expected sequence. The native default-off Settings capture
was also inspected: search highlights the correct row and the absent notification
service does not disable its Play control.

## Not verified / deferred

- **Audible playback was not verified on any real system.** This is the owner's
  desktop; every player invoked during verification was a fake recorder.
- Actual PipeWire versus PulseAudio behaviour, physical speakers/volume/muting,
  canberra sound-theme resolution, and a real machine with no installed sound
  theme. Missing files/players and all selection order cases use fake filesystem
  tests; they do not assert a desktop has usable theme audio.
- Abrupt termination of the whole app (SIGKILL/crash), as opposed to normal window
  close/re-exec. The normal shutdown path kills and reaps its child.
- Real notification daemon presentation, Wayland and accessibility interaction;
  this slice does not change their existing boundaries.
- Per-status sound selection/subpages, volume, launcher badges, bells and program
  message audio remain out of scope. No sound-name notification hint was added.
- No dependency, vendor, version, lockfile or Nix packaging change. No release,
  push, PR or tag.
