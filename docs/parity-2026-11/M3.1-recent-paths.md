# M3.1 — Recently used paths

Built on `a0d7505`; merged with `origin/master` at `d7a146b` (#90) before review, and the
parent re-ran the checks after that merge and again after the review fixes below.
This is the local-history slice of T78, building on
[Insert path](M3.1-insert-path.md) and [Go to directory](M3.1-go-to-directory.md).
The beta's default-on setting and per-host sharing are known; its recent-row
presentation was not captured. **This presentation is ours, not a claim of visual parity.**

## Shipped

- An accepted Insert path or Go to directory paste remembers its absolute path and
  folder flag. Each saved host keeps at most **10** paths, newest first. Reuse moves
  a path to the front without duplicating it, and updates its folder flag.
- On opening either browser, its ordinary first successful listing supplies the home
  directory for `~` display. The typed-path row stays first; **Recent** follows, then
  **In this folder** and the existing entries. The latter heading distinguishes the
  listing from history and appears only when recent rows exist. Go to directory
  offers only folder recents. The first recent is Down, Enter from the initial row.
- Recent rows use the existing row, truncation, selection, pointer and keyboard paths.
  Enter/click pastes; Tab descends a recent folder through the existing list request.
  Any field edit, including Tab descent and edits before the first response, hides
  recents for the rest of that opening, even if the original text is restored.
  The browser's own initial `~/` substitution is not a person editing the field.
- No recent rows means no headings, gaps or reordered entries: the old pixels remain.
- Settings → Terminal ends with **Path browser**, after Default shell and Titles,
  using `settings_kit` section/card/setting/footnote blocks and the existing switch.
  **Show recently used paths** defaults on. Its footnote says history is per host,
  on this computer, and turning it off forgets it. The actual label is searchable.
  Off clears all host lists, saves that erasure, stops recording and showing; on
  starts empty. There is no individual clear, pin, filter or second setting.

## Storage and boundaries

`workspace.json` has `recent_paths`, a map from saved endpoint to an ordered array of
`{path, directory}` records. This follows `MutedTab`'s endpoint identity, not a session
id or a temporary connection id. `terminal.show_recent_paths` is the one preference.
An empty map and a true preference are omitted by serde: old files load with no
new behaviour or serialization keys. Writes use `Workspace::save` and the existing
atomic settings writer, never a second writer.

Removing a saved host erases its list. Editing its endpoint drops the old list;
paths never migrate to another machine. Renaming its label or changing its default
shell preserves the list. Settings load also removes orphan endpoint lists,
duplicates, entries beyond ten and invalid paths; a false preference discards all
loaded history. Building recent rows validates again, including for state supplied
without the file loader. Valid means absolute, at most **4096 bytes**, and none of
`directory::refused`'s characters. The existing character predicate and limit now
live in `settings/recent_paths.rs` and are reused by the browser without changing
what they reject. POSIX quoting and paste refusal are unchanged.

A listing row supplies the folder flag. Insert path's typed row also uses an exact
matching child in the already-returned listing when available. An unmatched typed
Insert path has no known folder metadata and is not offered by Go to directory;
Go to directory's typed row for a name that was never listed may not be a folder, or
exist: it is typed as asked and not remembered. There is
no stat or extra listing to resolve this uncertainty. This does not change the
existing typed row's Tab behaviour.

Both Commands still use `upload.rs::paste_text`, the same captured-pane and live
checks, and exactly one `Command::Paste` through the same sender. The only input
plumbing change exposes acceptance as a boolean (`Term::try_send`, with ordinary
`send` retaining its old interface) so history is not recorded for a gone/paused
pane, disconnected host or closed command channel. This is **local acceptance**,
not a server delivery receipt. Nothing retries, presses Enter, adds a newline or
runs text. Clipboard handling is unchanged. Both actions remain `Remote::Never`,
unbound by default; no action, key or allowed-remote-set change was needed.

Recents themselves send **no request**, including no existence check. A deleted
path is still offered. Opening and descent use only the original browser reads;
terminal contents, layout, ownership and server configuration are untouched.

## Not verified / limits

- Native checks cover local Unix Rex, X11 and Bash, not SSH/HTTPS, Wayland, other
  shells, IME or screen readers. Per-host/session separation and edited-file
  validation are headless tests, not native multiple-host acceptance.
- No beta capture exists for the recent rows. No claim of matching its layout,
  ordering policy or cap. This is a bounded client-local convenience.
- No stale-path check, canonicalization, symlink resolution or inference from shell
  history. Paths are deduplicated by their exact absolute spelling. A typed path's
  folder flag is only the listing knowledge described above.
- POSIX quoting still goes into whatever program or partially typed command is in
  front. It does not make text safe inside an existing shell quote. Nothing here
  changes the deliberate no-Enter policy.
- Native acceptance observes the terminal and private settings file, not client wire
  packets. Exact lack of extra history requests is covered by headless channels.
- T79's shortcut badge, searching/filtering/pinning/individual clearing of recents
  and any execution mode remain out of scope. No issue in the brief required them.
