# `rex.ui` script prompts (Slice 2, Closes #144)

Completes **#144**, building on Slice 1 (`#172`, `src/connection/prompt.rs`, `src/connection/actions.rs`, `HostCommand::Prompts`, `HostCommand::PromptReply`, `HostModel::prompt_events`, and `settings::Host.prompts`). This slice wires the interactive prompt queue, anti-spoofing modal, waiting toolbar chip, Commands entry, per-host Settings switch, zero-PTY-leak guards, and live API 21 X11 verification into the Rune front end. Verification date: 2026-11-24 (Pacific Standard Time), branched from `origin/master` (`76ae653`).

## Scope

- **App prompt state machine and queue (`src/app/prompts.rs`, `src/app/workspace.rs`, `src/connection/actions.rs`):**
  - Passes `host.prompts` into `HostConnection::spawn_with_prompts` at worker startup (eliminating any first-connection bootstrap refusal race while keeping `HostConnection::spawn` default-off for probes), and sends `HostCommand::Prompts(host.prompts)` on Settings toggles (`settings::Host.prompts` defaults `true`, persisting only opt-outs). Turning the switch off sends `HostCommand::Prompts(false)` (immediately refusing any active prompt on that host) and clears local waiting/open prompt state for that host. Current-epoch prompt events published during bootstrap before `connected` flips to `true` remain buffered until connected so intervening UI wakes cannot drop them.
  - Keeps arrival-ordered prompt state (at most one active prompt per host) in `Workspace.prompts` outside `Panel`: draft text, filter query, selection index, checked item IDs, inline error message (`ReplyRejected` / `bad_request` / `RequestTooLarge`), open timestamp, in-flight lock, and per-host 10-second post-cancel cool-down.
  - Exposes `HostModel::actions_in_flight` from `connection/actions.rs` so the UI knows whether this client has a `client.action` awaiting a response on that host.
  - Auto-opens a newly arrived prompt (`PanelKind::Prompt`) only when all five guards hold: no panel is open, the window is focused, not in copy mode / shortcut recorder / divider or floating-layer drag / pending key sequence / focused find bar, either `actions_in_flight > 0` for that host or at least 750 ms have elapsed since the last keypress, and the host is not inside a 10-second post-cancel cool-down. Otherwise the prompt waits as a toolbar chip without clobbering any open panel or raising the window.
  - `reconcile_prompts()` demotes an open prompt cleanly back to Waiting whenever a local panel replaces `PanelKind::Prompt`, preserving draft text, checked IDs, selection, and rejection errors. Opening a waiting prompt from Settings preserves Settings via `keep_back` so answering, cancelling, or host termination returns cleanly to Settings.
  - Accident guards: Enter repeats are ignored, submit (keyboard and pointer) is inert for 300 ms after opening, and while a reply is in flight both primary submit and Cancel/Escape/close-X are disabled so the entry survives until server settlement (`Accepted`, `ReplyRejected`, `NotFound`, `Failed`, or `Ended`). Clicking the dark scrim outside the modal does nothing (because Cancel terminates the prompt for every connected client). Quitting or removing a host sends nothing.
  - Crisp notices cover answered on another device (`EndReason::Answered`), timeout (`EndReason::Timeout`), server withdrawal (`EndReason::Cancelled`), host disconnect (sticky unconfirmed-answer notice when a reply was in flight; open vs waiting nothing-sent notice otherwise), answer not used (`ReplyOutcome::NotFound`), unconfirmed reply (`ReplyOutcome::Failed`, sticky), and oversized dropped offers (`PromptEventKind::Dropped`). `ReplyRejected` keeps (or reopens if demoted with no panel open) the modal with a clamped 2-line inline `DANGER` error and the user's draft intact.
- **Anti-spoofing modal UI (`src/app/prompts.rs`, `src/app/dialogs.rs`, `src/app/widgets.rs`, `src/app/mod.rs`):**
  - Mounted directly on `dialogs::modal_frame_persistent` (never through `list_popup`) with a client-owned accessible dialog name (`Question from <saved host label>`), 520 pt wide (`input`) or 560 pt wide (`pick`), clamped to `min(width, 90% viewport width)` and `85% viewport height`, 22 pt padding, 14 pt gaps, using `theme.rs` tokens only across all four dark palettes.
  - Client-owned attribution chrome that script payloads cannot alter: host kind icon + `Question from <saved host label>` (endpoint as tooltip) and close-X button, script `title` at medium 15 pt (never the strong 17 pt local-dialog title slot, clamped to 2 lines below 560 pt height), subline `Asked by action <name>` (mono) or `Asked by a script on this host`, and destination footnote (`What you type is sent to <saved host label>.` for `input` and `allow_other` pick; `Your choice is sent to <saved host label>.` for pure `pick`). Every script string renders in its own text element so RTL/bidi text cannot reorder client chrome.
  - `input`: single text field initialized from `value` and `placeholder`, enforcing the 4,096-character cap with an inline hint when hit; Enter submits `PromptAnswer::Text` (empty allowed); Tab cycles field -> Cancel -> primary button; default confirm label `"Submit"`.
  - `pick` (single and multiple): 34 pt filter field (case-insensitive substring match over `title`, `subtitle`, `detail`); rows via `widgets::list_row` at 28 pt (or 40 pt across the list when any item has a non-empty `subtitle`), 15 pt icon slot mapping all 16 named stroke icons (`document, folder, branch, terminal, code, server, database, package, globe, link, person, tag, clock, star, gear, plus`) plus generic fallback, trailing detail capped to 96 pt, up to 10 visible rows (at least 3 rows at 640x480) with scroll thumb and overflow hint. Single pick supports `allow_other` (`Use "<typed>"` synthetic first row submitting `PromptAnswer::Text(typed)`), exact raw opaque `id` submission, and 35% opacity disabled primary button (`"Choose"`) when nothing is selectable. Multiple pick adds a check column, `<N> of <total> chosen` count in the filter row, Tab / Shift+Tab toggle-and-step, click-to-toggle, check persistence across filtering, and submission in original listed order (empty list allowed).
- **Waiting toolbar chip, Commands entry, Settings switch, and zero-PTY-leak guards (`src/app/toolbar.rs`, `src/app/title_row.rs`, `src/app/commands.rs`, `src/app/settings_view.rs`, `src/app/settings_nav.rs`, `src/app/input.rs`, `src/app/term.rs`):**
  - Toolbar chip in `WARNING` at 28 pt height (`Question · <saved host label>` or `<N> questions`), sitting after the pending-sequence chip, floating when the toolbar is hidden, opening the oldest waiting prompt on click, and fitting cleanly at 640x480 alongside live chips.
  - Commands lists `Answer question from <saved host label>…` as an `Intent::OpenPrompt` (not a registered remote action) whenever a prompt is waiting.
  - Settings -> Remote Hosts adds a per-host **Allow script prompts** switch beside **Remote control**, persisted in `settings::Host.prompts` and indexed by Settings search.
  - While `PanelKind::Prompt` is open, `input.rs` (`on_key`, `on_key_up`, `on_ime`) and `Term::try_send` (`prompt_open` defense-in-depth) block all PTY input (keys, repeats, releases, IME, paste, mouse), opening the prompt modal clears pre-modal held-key `forwarded` identities, and `remote.rs` refuses `Remote::View` performs while consented `client.tab.mute` (`Remote::TabState`) stays allowed behind dialogs.
