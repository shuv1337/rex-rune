# M3.1 — Go to directory

Base: `bc74ab8` (after #81). Builds on the Insert path browser of
[M3.1-insert-path.md](M3.1-insert-path.md); read that record for the browser itself
(listing, coalescing, reply matching, refused characters, quoting, the detached request).

## The decision this slice rests on

The roadmap and the beta have Go to Directory type `cd <path>` **and press Enter** when
the foreground program is a shell. The client cannot see what the prompt already holds.
If text is typed there (say `rm -rf `), Enter would run that text with the `cd`
appended. The question went to the decision queue with four options (type `cd` without
Enter; type and Enter as the beta; clear the line first; skip the feature) and the
orchestrator decided on 2026-11-12: **type `cd <quoted path>` and do not press Enter;
the person presses it.** Nothing in this slice sends a key.

A consequence: there is no check that the foreground program is a shell. Without Enter,
typing `cd /path` into another program is the same as Insert path there: visible,
pasted text that runs nothing. Adding a `terminal.process` read to refuse it would cost a
request and could refuse wrongly on stale data.

## Shipped

- `pane.go_to_directory`, **Go to directory…** in Commands and a row on Settings →
  Shortcuts. `Remote::Never`; `requires_person` covers it, so neither `client.perform`
  nor a host-returned client action can open it; the allowed set is still exactly eight.
  Unbound by default (the roadmap's `Ctrl Shift G` is left free), assignable and
  removable through the recorder.
- The Insert path browser with `go` set: `terminal.list_dir` is asked with
  `files: false`, and an entry a server marks as a file anyway is dropped, so only
  folders are offered. (A server that ignored the flag without marking its entries
  would show files as folders; choosing one types a `cd` that fails at the shell.) Title “Go to directory · <host>”, placeholder “Folder on the terminal's
  machine…”, first row “Go to typed folder”, the rest “Folder”. Tab descends, and the
  next read is folders-only too.
- Choosing a row closes the browser and sends one paste of `cd ` followed by the quoted
  absolute path, through `paste_text`: the captured pane, on its own host, or a notice
  if it is gone or not live. No Enter, newline or trailing space, nothing retried.
  The path is absolute, so it cannot be read as an option and `--` is not needed.
- The refusal notice shared with Insert path now reads “Nothing was typed: the terminal
  is not live.”

Everything else is unchanged Insert path behaviour: the typed path is the first row
(a partly typed name there is typed as it stands and fails at the shell if it is not a
folder), control and invisible formatting characters are refused, paths over 4096 bytes
are refused, quoting is POSIX single quotes when needed, and the text goes to whatever
program is in the foreground.

## Verification (parent, 2026-11-12 PST)

- `cargo fmt --all -- --check`, `cargo test --locked --all-features`, `cargo clippy
  --locked --all-targets --all-features -- -D warnings`, `cargo build --locked --release
  --bin rex-linux`: results in the PR description.
- Headless tests in `src/app/directory_tests.rs`:
  `go_to_directory_lists_folders_and_types_cd_without_enter` (folders-only request,
  files dropped, captured pane kept when focus moves, exactly one command and it is
  `cd '/home/dev/my dir'` with no newline),
  `go_to_directory_types_the_typed_folder_and_refuses_what_insert_path_refuses`,
  `go_to_directory_is_never_remote_and_a_host_cannot_open_it`, and two isolated
  real-font captures (`go_to_directory_draw_large`, `go_to_directory_draw_minimum`).
  The existing wiring tests cover the Commands row, the Shortcuts row and the remote
  decision for every registered action.
- Private X11 acceptance: `scripts/insert-path-x11.py` gained a Go to directory
  segment. On a private Rex server, Xvfb and HOME, with a real Bash prompt, choosing the
  folder `my dir` left exactly `cd '<tree>/my dir'` in the readline buffer, the prompt
  counter unchanged (nothing ran), and only after the script's own Enter did `cd`
  succeed and `pwd` report that folder.

### Independent review

Cursor-pool Opus reviewed `682f4fd` and approved the product code with no change: one
paste and no key on every route, no newline or control character possible, the path
always absolute, folders only (a link to a folder is offered, as the protocol defines
`file`), Insert path unchanged with `go` false, and the wiring complete with no
default binding. It asked for two small fixes, both made:

- The native script's later 640×480 Insert path check listed the empty `my dir` the
  shell had just moved to, and passed only on text in the terminal behind the popup.
  The script now returns to the tree first, and asserts on a row that appears only in
  the browser. It also adds a file `my file`, so the run shows files are left out.
- The changelog entry said “(M3.1)”; it now says “(partial M3.1)”, since recent
  paths and the shortcut badge are deferred.

Left as a follow-up: the first row offers “Go to typed folder” for a partly typed
name that is not a folder; nothing runs and `cd` fails harmlessly if Enter is pressed.

## Not verified / deferred

- SSH or HTTPS hosts, Wayland, shells other than Bash. fish and csh read single quotes
  differently for some characters, as recorded for Insert path.
- Recent paths (T78), the shortcut badge (T79), and any mode that presses Enter.
- With this, the G01/G02 and T76/T77 rows are covered except for pressing Enter, which
  is a deliberate difference from the beta.
