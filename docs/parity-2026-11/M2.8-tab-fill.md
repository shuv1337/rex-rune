# M2.8 — toolbar tabs fill available space

First, deliberately small M2.8 slice on `e0c8f133a550bfb75920ee2166e6f2832c27b3e0`
(after #70). Validated locally 2026-11-11 (PST). This is not the complete tab
appearance roadmap item or a restoration of preserved Wave 2.

## Implemented

**Settings → Interface → Sidebar and tabs → Tabs fill available space** is one
existing-kit switch, **off by default**, saved immediately as
`interface.tabs_fill_available_space`. Missing keys preserve the old behavior.
The actual label is indexed by the existing Settings search/history machinery.
Its helper is “Only toolbar tabs share the available width.” No new page, action,
shortcut or remote surface.

When enabled, the existing toolbar track takes the spare horizontal space and
its pills share that width with centred content. Each pill keeps at least 96 pt,
enlarged to reserve its existing icon, padding, 40 pt of name, and whole activity
or muted marks. Status-word sizing uses the preserved prototype's generous
7 pt/character estimate; no new font measurement or icon machinery. When the
combined floors do not fit, the existing horizontal scroll viewport, left/right
buttons and selected-tab reveal remain in charge. Names truncate before status
words; accessible labels, tooltips, progress, context menus and menu-based reorder
remain unchanged. There is still no close button on a pill.

Identity, Commands/New tab/Settings/Close, live Downloads/sequence chips and at
least 48 pt of native window drag space take priority. No tab means no empty
track; the drag space grows as before. Always/On hover/Hidden keep their existing
row/overlay semantics. Sidebar rows do not change, and closing a sidebar that
holds tabs makes the saved fill choice effective in the toolbar again.

Only horizontal chrome sizing changes. The switch saves the preference and asks
the existing poll to reveal the selected tab again; it sends no input, ownership,
resize or server layout request. No changes to #70 header fading, #68 padding/
outline/layout callbacks, #67 metrics/font isolation, recorder, generated-title
resolution, Settings history, Downloads/consent, terminal input or selection.
Updater files, page and wiring, vendor/dependency/lock files are untouched.

### Real-font inspection and baseline

Captures ran individually with Inter / IBM Plex Mono at 1024×700 and 640×480:
fill off/on, overflow with Downloads off/on, and the Interface switch. Inspected
both sizes: the new label/helper fit, the existing toolbar controls and drag
space survive, names truncate, and status/progress stay in the existing style.

For a concrete default-pixel comparison, the capture fixture was also compiled
with **the original `e0c8f13:src/app/toolbar.rs`**, then the implementation restored.
The complete default-off frame is byte-for-byte identical at both sizes (zero
changed pixels). Off→on changes only the toolbar: 15,157 pixels at normal size,
294 at minimum; everything below its 52 pt row is pixel-identical. The latter
has no spare width and changes only the centring inside the existing pills.

### Private native acceptance

`REX_BIN=<release binary> python3 scripts/tab-fill-x11.py` passed on private Rex
API 13, Xvfb and openbox, with isolated HOME/XDG/config/server/display and no
clipboard use. It checks actual-label Settings search and saved activation;
the server's **complete terminal size/owner response** is unchanged by the
preference. Header captures show fill changing the toolbar.

Eight real tabs exercise next/previous scroll buttons (previous restores the
original toolbar pixels), Ctrl Tab/reverse navigation, pointer selection,
last-tab reveal, right-click menu, saved mute and server-confirmed Move left.
A 640×480 capture follows native resize. All eight raw PTY recorders are empty
except for exactly one deliberately typed `x` in the final selected tab: no
Settings, navigation or menu key leakage.

## Limits and deferrals

At 640 pt with a long identity and Downloads, the track can be narrower than one
96 pt pill: the selected pill is only partly visible, as with the existing
scroll/reveal policy. In the most crowded status fixture only its trailing
percentage is visible; both arrows and context-menu targeting still work. This
slice does not shrink protected controls, invent a responsive toolbar or promise
that every status/name fits in the viewport.

Native Wayland/compositor, IME, screen-reader, fractional-DPI and multi-client
native focus acceptance were not run. Native Downloads combined with overflow
was not exercised here; its geometry/captures and channel checks are headless,
and the existing download suite passed. Native script click coordinates are tied
to the current fixed test geometry. No new theme/contrast claim.

Icon count/colour/theme/program-icon work and a live settings preview remain
**deferred M2.8**, with no placeholder controls. No focus-follows-mouse workaround,
move-to-new-tab (#44), theme licensing changes, updater work or speculative
robustness. Old `rex-parity/{a,b,c}` and unrelated untracked evidence were untouched.
The parent owns independent validation, review, PR/CI/merge; this work includes no
push, version bump, tag or release.
