# M3.3 — Pair device (partial)

Verified **2026-11-12 (PST)**, on Linux. This is local address sharing, not a
pairing protocol or a reachability check. **Implemented and independently decoded;
an actual phone scan / Rex accepting the host on another device is not verified.**
No release work, dependencies, lockfile, vendor, version or settings changes.

## Shipped behavior

Settings → Server has a **Pair device** row under Tailscale address, with a **Pair**
button when the active host is connected and its cached HTTPS report says
`available` with a usable sanitized `https://` URL. Missing, pending, off,
non-HTTPS, malformed and disconnected reports do not offer Pair, and the row says
what is needed. Copy keeps its original last-reported behavior, including when
disconnected. (The delegate's version put Pair beside Copy on a row relabelled
“Tailscale address · Pair device”; the parent split it into its own row.)

The code holds the **bare origin** when the reported address has no path, for example
`https://build.tail1234.ts.net`, as the code Rex for macOS shows does. The page's
address and Copy write the same URL with the trailing slash a URL writer adds
(`https://build.tail1234.ts.net/`); that one character is the only difference, and the
text under the code is exactly what the code holds. An address with a path is kept
whole. The zbarimg outputs listed further down were recorded before this change and
show the slash; the parent's four retaken captures decode to the address without it.

**Pair device…** (`client.pair_device`) appears in Commands → Host, disabled when
unavailable, unbound by default, with a Shortcuts title/category and effective-key
hints. It is `Remote::Never` and `requires_person`; the pinned remote allowed set
and its test are unchanged. Both entry points use the same dialog.

The dialog shows a black QR on white with a four-module quiet zone, the saved
host label, the exact encoded address as selectable, non-link text, instructions
to scan with Rex, and a last-reported/reachability qualification. **Done** and
Escape restore the originating Server Settings panel, including its navigation
state. From Commands they close the dialog. A host switch, disconnect, new epoch
or changed HTTPS report hides the old code and address immediately; it does not
silently replace them with another host's code. Reopen for that host's new facts.

The shared `server_page::tailscale_address` extracts the same cached fact for
Copy, display and encoding and calls the page's existing `address` sanitizer.
No second sanitizer in the product. Credentials, query and fragment are removed;
URL canonicalization (including an empty path becoming `/`) is shared. Existing
URL paths remain visible. No address is inferred from SSH forwarding, this
client's Tailscale, listeners or DNS. No server status request, session creation,
terminal input, server configuration or clipboard write occurs on dialog entry.

An address longer than **213 bytes** still opens the dialog: it says the address
is too long to show as a code, with the complete selectable text (wrapping and
scrolling when needed), and Done. No truncation is encoded and no fake code is
shown. This does not add a setting.

### Drawing and sizing

`pair_device.rs` computes the matrix **once at open**, then caches horizontal
black runs. Rune already paints pixel-snapped rectangular fills well; this avoids
image filtering and a separate image upload/cache, with fewer than 1,000 run
elements even for the tested version 10 symbol. The code is centered, with a
280 pt budget at 1024×700 and 240 pt at 640×480; module size is rounded down to
integral **device pixels**, accounting for device scale and interface zoom. The
white and black are deliberately independent of chrome themes. Everything else
uses the existing modal frame, title, value and pill components and chrome tokens.

The realistic captured address produces a version 3 symbol. At minimum size its
card is 222 pt square, with 6 device pixels per module at 1× and 12 at 2×. At
1024×700 it is 259 pt at 1× (7 px modules) and 277.5 pt at 2× (15 px modules).
A physical phone at arm's length has **not** been tried; size alone is not proof.

## Encoder and independent verification

`src/qr.rs` is library-only: Model 2, byte mode, error correction **M**, smallest
version **1–10**, GF(256) Reed–Solomon over 0x11d, correct short/long block
interleaving, all fixed patterns, BCH format/version bits and all eight masks.
The public API returns a matrix or `TooLong`. Empty input is supported; no ECI,
structured append, Micro QR, other error levels or versions above 10.

`tests/data/qr/*.qr`: **22 independent reference matrices**, generated by
`/usr/bin/qrencode` **4.1.1**, `-l M -8 -m 0 -t ASCIIi`, using stdin bytes:

- One byte (`a`).
- `https://name-rex.tail123456.ts.net/`.
- UTF-8 `https://example.net/été/日本`.
- Exact byte capacities of every version: **14, 26, 42, 62, 84, 106, 122, 152,
  180, 213**. Data cycles ASCII bytes 33–122 rather than allowing alphanumeric
  mode optimization.
- Capacity plus one for each version 1–9, covering each version transition.

**22/22 exact whole-matrix matches** after reading the reference mask from its
format bits and forcing that mask internally in tests. The public encoder still
chooses its own mask. **17/22 own-mask agreements**; the five differences are
investigated, not ignored:

| Input | qrencode mask | Our mask | Our scoring: reference / chosen |
| --- | ---: | ---: | ---: |
| one byte | 4 | 5 | 1060 / 1028 |
| v1 full, 14 bytes | 0 | 6 | 1095 / 1025 |
| v3 full, 42 bytes | 5 | 2 | 1241 / 1203 |
| v6 full, 106 bytes | 1 | 6 | 1871 / 1829 |
| v9 full, 180 bytes | 7 | 2 | 2652 / 2574 |

Our N3 counts both qualifying orientations of a finder-like 1:1:3:1:1 core,
including scaled ratios and the light exterior. libqrencode 4.1.1's
[`Mask_calcN1N3`](https://github.com/fukuchi/libqrencode/blob/v4.1.1/mask.c)
uses `if … else if`: a core with qualifying light space on both sides counts
once. It also rounds the dark percentage before N4; ours uses the exact ratio.
A test-only model of those rules recomputes all eight candidate scores and
reproduces **all 22 reference mask choices**. Every differing choice has a lower
score under our rules; it is not attributed vaguely to a tie. `qr-tests.log`
includes both scores and the eight qrencode-rule scores for each difference.

Five encoder tests cover these matrices, published M format strings and v7–10
version strings, the degree-10 RS generator and HELLO WORLD parity example,
codeword/data/byte capacity tables, 214/1,000-byte rejection, empty input and N3's
both-sided/scaled/exterior cases. The golden script is committed for provenance;
it is not run to manufacture expectations during the Rust suite.

`scripts/qr-verify.py` renders **our** `examples/qr_dump.rs` PBM output to PNG,
then requires `zbarimg --quiet --raw --set '*.binary=1'` to return the exact input
bytes plus its output newline. **22/22 symbols decode**, including UTF-8, every
version, all full-capacity inputs and all mixed-length block layouts. Additionally,
**4/4 complete dialog captures decode exactly**. zbarimg is deliberately not a
Rust/CI test dependency. No dependency was added for the encoder or its rendering.

### Regression evidence

`regression-disabled-dark-module.log`: the committed golden comparison fails
(exit 101) with the fixed dark module omitted in a **fault-injected scratch copy**
of the actual encoder. Production code was never disabled during concurrent
builds. `fault-qr.rs` preserves that experiment. The untouched implementation
passes all five tests in `qr-tests.log`.

two disposable Unix-socket Rex servers, private HOME/XDG directories, private

Final artifacts: `native-lbncx0ui/`, log `native-isolated.log` (exit 0).

Observer API counts are recorded separately in `results.json`, not claimed as
client wire counts. As in the original Server acceptance, no client traffic
interceptor exists; exact zero-command evidence is the headless channel test.

cleanly but prompted tightening the script to a no-activation bus. Final evidence
above uses that tightened isolation, with no portal activation warnings.

## Not verified / limits

- An actual phone scanning at arm's length; Rex on another device accepting it.
- Real Tailscale HTTPS reachability, login, permissions, expired addresses or any
  pairing protocol. The dialog explicitly promises none of these.
- Native dialog decoding (private servers had no usable Tailscale HTTPS report).
- Physical HiDPI, fractional display scales, native Wayland, macOS or Windows.
  New Rust code is platform-neutral; cross-platform CI is still required.
- Screen-reader behavior; the code has an image label and the exact address is
  selectable text, not a claim of assistive-technology validation.
- Scanning/importing hosts, tokens, server controls, uptime, Tailscale changes,
  per-listener QR and non-Tailscale QR remain out of scope.

No problem with the requested plain-address payload was found, but its beta
screenshot is not evidence of another Rex client's acceptance. Existing Server
facts still retain their as-reported timestamps and paths; that policy is not
changed by this work. The historical released changelog's “pairing deferred”
statement is preserved; only Unreleased documents this new slice.
