Base: `07c9c7f` (master, M2.6/#67). Implemented and checked on 2026-11-11 PST.
This is **partial M2.7**, not the preserved Wave 2 or the complete roadmap item.
The release-timing scope explicitly defers focus follows mouse and header fading.

## Shipped surface

- Settings → Terminal → Layout: **Horizontal padding** and **Vertical padding**, independent 0–32 pt steppers, 8 pt each by default.
- Settings → Interface → Panes: **Active pane outline**, Auto / On / Off. Auto preserves Comfortable card outlines and no Compact outline. On also outlines the focused pane in a Compact split. Off removes the focus decoration, not drop/menu target cues. A single edge-to-edge pane has no outline.
- The existing Settings kit supplies rows, wrapping, scrolling, anchored choices and search indexing from the actual labels. No new page, action, shortcut or remote permission.

`pane_padding` stays top-level. With absent/null `interface.pane_padding_vertical`, it still applies to all four sides, including subsequent edits to an old file. The first UI edit pins the other axis to its displayed value. `interface.highlight_active_pane` is absent/null for Auto, true for On, false for Off; Auto can be restored in the UI. Unknown toolbar modes retain the existing Always fallback.

These are local preferences. Terminal colours, alpha, split placement, cursor/selection policy, generated titles, Downloads and input handling are unchanged. Padding uses the existing `resize_if_owner` path, never a claim. Find's apron and bar use the vertical bottom inset as well as the horizontal sides. Toolbar Always/Hover/Hidden is untouched.

### Implementation detail found by live acceptance

Repeated one-point vertical edits initially exhausted Rune's layout-feedback budget before the next whole row boundary; the cached grid rectangle stopped updating. The pane's layout callback now uses `on_layout_tx` and avoids a redundant view pass when only the origin/cell slack changed and the find corner stayed the same. It still stores every rectangle and calls the existing ownership-aware resize path. Whole-grid or find-corner changes still rebuild. No vendor patch, new geometry path or ownership bypass was added. Live acceptance crosses the boundary with repeated presses, not one large preference jump.

The padding/outline semantics were adapted from our read-only preserved `cc8bdad` reference. No ohporter commit was transplanted in this slice.
