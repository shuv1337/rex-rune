## Behavior and compatibility

The Terminal page uses current Settings navigation/search, headings, cards and
footnotes. Typography, Cursor and Selection get **steady preview wells**, drawn
by the terminal row/cursor renderer. Existing typography controls, padding, theme,
host shells and generated-title switch remain. Style and selection-colour lists
use current anchored pickers over Settings. The settings-file path moves to About.

Only these new keys live under `terminal`:

| Key | Default | Choices / meaning |
| --- | --- | --- |
| `cursor_style` | `"block"` | `block`, `bar`, `underline` |
| `cursor_force` | `false` | Override explicit program shape locally |
| `key_sequence_hints` | `true` | Both toolbar-row and floating chips |
| `copy_on_selection` | `false` | Copy a completed pointer selection on release |
| `primary_selection` | `false` | Also own PRIMARY; middle-click paste |
| `selection_foreground` | `"theme"` | `theme`, `cell_foreground`, `cell_background` |
| `selection_background` | `"theme"` | Same choices |
| `selection_rounded` | `false` | Round exposed outer corners, 3 pt |

Old files and partial groups load with these defaults. Unknown enum strings fall
back to Block/Theme. Existing top-level `generated_titles`, `font_size`,
`font_family` and `font_fallbacks` stay top-level and retain their values/defaults.
Unlike preserved W2, **rounded selection defaults off**, preserving existing
selection pixels. Ordinary terminal output colours, font metrics and geometry
are unchanged. A cell-derived selection foreground equal to its fill uses the
cell's other colour; Theme/Theme preserves the previous theme behavior exactly.
Wide-cell tails share the selected glyph's fill; internal row joins stay square.

Copy waits for the worker frame matching the release's selection revision, then
consumes it once. Press/motion, plain focus clicks, Select all, cleared selections,
focus loss, hidden panes and opened panels do not trigger accidental copies.
Selecting/copying sends no size or ownership claim. PRIMARY uses arboard on a
separate worker (already present transitively; the lockfile only gains the direct
root dependency). Middle paste is opt-in, on release, not after a drag, and never
while the program tracks the mouse, including Shift override. It rechecks the
visible session/target, focus, panel, setting and live/mouse state after the read;
paste goes through the existing one-shot terminal input path, not a replay queue.

No new action IDs or remote permissions: these are existing Settings controls.
The remote allowed-set tests remain unchanged. Hiding sequence hints never clears
the pending sequence or changes consumed-prefix/release handling.

### Cursor semantics were established before implementation

`tests/cursor_policy.rs` first exercised the **current vendored Ghostty decoder**:
encode/decode an untouched terminal and one with explicit `CSI 2 SP q`, then set
its local default to Bar. The untouched terminal draws Bar; the explicit request
still draws Block. Changing the default to Underline leaves that Block until
`CSI 0 SP q`, which restores Underline. The server-side terminal stays unchanged.

`TerminalStream` tests repeat this through actual snapshot framing and live bytes.
The local `CursorStyle` data command changes the decoder's default, including
subsequent snapshot restores, without any server request. Force style overrides
only drawing; unfocused panes still show a hollow block. Blink requests still draw
steadily. There is no heuristic treating every Block as an unspecified cursor.
