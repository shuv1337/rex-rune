# M3.1 — Insert path (focused slice)

## Shipped

**Insert path…** in Commands and `pane.insert_path` open a palette-style browser for the
pane focused when the action ran. Settings → Shortcuts lists the action, bound or not.
The captured pane never follows later focus; its disappearance closes the browser with
“That pane is no longer available.” The action is `Remote::Never`; the pinned remote
allowed set is unchanged. Returned client actions cannot open this file dialog either.

Opening reads the terminal's current working directory with an empty `terminal.list_dir`
path and `files: true`, rather than trusting OSC 7 or reading this computer's filesystem.
The returned home directory supplies `~` in the initial field and path labels. The part
after the last slash filters the listed parent, case-insensitively; a trailing slash lists
that directory. Spaces are not trimmed. The first row of a successful listing inserts the
typed path; the remaining rows are sorted case-insensitively, with deterministic name
ordering for ties and plain **Folder** / **File** details. Dot names appear only with a dot
prefix. Truncated results say “Some entries aren't shown. Type more of the name.”

Up/Down select, Enter or a click inserts, Tab descends a selected directory, and Escape
or a press outside closes and returns to terminal input. Existing list rows, field,
selection outline, captured-target outline, scrolling and effective-keymap hints are
reused. There is no hint footer, status dot, extra menu badge or extra pane-menu row.

## Decisions

- **Default key:** unbound. `Ctrl Alt I` already belongs to **Report an issue**. The action
  can be assigned and removed through the existing Shortcuts recorder/file layers.
- **Tab:** descend on unshifted Tab. Existing one-control list popups already consume Tab,
  so no field/action traversal is displaced. Shift-Tab stays in the field. Right keeps its
  text-editing meaning, rather than unexpectedly descending while editing a path.
- **`~`:** display it for the reported home; insert the **absolute path returned/resolved by
  Rex**, not a quoted literal tilde or a mixture of expansion and quoting. Descent uses an
  absolute directory path. There are no extra `pwd` or `process` requests.
- **Insertion:** no trailing space, newline or Enter. `upload.rs::paste_text` sends the
  same `Command::Paste` event to the terminal that clipboard text is sent as, after
  checking that the captured pane still exists and is connected and live; otherwise it
  says “A path can be inserted only into a live terminal.” (or that the pane is gone).
  Clipboard paste itself is untouched: the parent reverted an earlier draft that had
  rerouted it through this function and added a notice to it. Whatever ownership
  behaviour a paste event has is unchanged.
- **Quoting:** POSIX single quotes only when needed. Embedded `'` becomes `'\''`; the safe
  unquoted alphabet is ASCII letters/digits plus `/`, `_`, `-`, `.`. Empty strings quote
  as `''`; non-ASCII is preserved inside quotes. The helper prefixes a relative leading
  `-` with `./`; browser choices are absolute already. Empty path components are preserved.
- **Refused characters:** reject, not encode. `directory::refused` covers Rust
  `char::is_control` (C0, DEL, C1), the line and paragraph separators, bidirectional
  controls, zero-width space, word joiner, byte-order mark and tag characters. Typed
  paths containing one get an inline message. Returned entry names containing one, or a
  slash, empty names, `.` and `..` are omitted; a returned directory path containing one
  or not absolute is refused. No raw control can reach the paste from a choice, and an
  invisible character such as a right-to-left override cannot disguise a name. This is
  not a defence against look-alike letters, and the zero-width joiner and non-joiner are
  kept (invisible between Latin letters) because scripts and emoji sequences need them.
  The set also covers soft hyphen, combining grapheme joiner, Mongolian vowel separator
  and the Hangul fillers. Typed paths over 4096 bytes are refused without a request.
- **Requests:** send the current name `prefix` on every read (including when narrowing a
  truncated listing). No speculative cache, polling, prefetch or automatic retry. An edit
  while a request is outstanding replaces the desired text; when that request ends, at
  most one read for the latest edited text follows. Rows clear while reading so old paths
  cannot be chosen. A failure waits for another edit.
- **Compatibility:** no guessed minimum API revision. An old server's `method_not_found`,
  `revision_too_low` or `not_supported` refusal gets the inline update-Rex message.

## Boundaries and implementation

`src/app/directory.rs` owns browsing, splitting, filtering, sorting and quoting separately
from the insert action. `src/connection/directory.rs` owns the read-only request and reply.
A request carries its id, connection epoch, target session/block, deadline and a weak
browser-lifetime token. An unsent request is discarded after close; an already-sent read
can finish but cannot revive a closed browser. Replies match the pending id and epoch,
and an answer for earlier text never replaces the newer desired listing. Disconnect or
a new epoch clears even a completed listing, without requesting anything automatically.
The eight-second budget includes queue age when checked before sending; a request already
waiting behind another host operation cannot report its expiry until the worker reaches it.
Once sent, the listing is **not waited for inline**: it is sent detached, as the server's
version and status reads are, with one in flight per host, so keys, events and other
requests on that host keep flowing while a slow filesystem answers.

The host's list branch bypasses the ordinary mutation/reconciliation path: it sends only
`com.superlogical.terminal.list_dir` and records its result. It never takes ownership,
resizes, changes sessions/layout, uploads, downloads or sends PTY input. Insertion closes
the browser first and sends exactly one paste, never replayed. The short inline messages
cover `missing`, `not_dir`, `denied`, unsupported methods, failed requests, timeouts and
disconnection. Request failures do not disconnect the host just to retry the listing.

No dependencies, settings, generated API, vendor files, lockfile, versions or release files
changed. The only changelog addition is under Unreleased → Added.

### Private native acceptance

`scripts/insert-path-x11.py` launches its own Rex server, Xvfb and window manager, private
HOME/XDG directories, no real clipboard and no real server/display. Its tree contains
`a space`, `Alice's`, `.hidden`, a directory with a child, and a newline-bearing name.
It opens the browser through Commands, observes the real listing, reveals the dotfile,
descends with Tab, closes with Escape and compares the server's size/owner and session
view before/after browsing. It captures both window sizes and the missing-directory error.

For each space/apostrophe name, the shell already contains `ls -d `. A private Bash
readline binding records the **exact** editable line after choosing a row, without
accepting that line. The prompt counter stays unchanged until the script sends Enter.
Only that explicit Enter runs `ls`, which resolves the chosen file and reports exit status
0. `results.json`, terminal before/after text, raw captures and OCR output retain evidence.
Owned app/window-manager/Xvfb/server processes are stopped by PID and waited for.

### Test-run environment and earlier failures

The first full run used the required long scratch path directly as `TMPDIR`. Six existing
download UI tests assume a short temp path outside HOME and failed on legitimate tilde/
ellipsis formatting (already tracked as papercut `pc_e730598ef23b`). Three menu inventory
assertions also caught an unnecessary new pane-menu row; it was removed, keeping this
slice's requested Commands/action entry points. No existing assertions were weakened.

A `/proc/self/fd/9` scratch alias was unsuitable for installer subprocess fixtures; that
run was interrupted by PID. The final suite instead uses an **isolated user/mount
namespace**, binding the scoped scratch `tmp/` directory at `/mnt` only inside that
namespace. The real filesystem storage remains under the required evidence root; no
other workspace or host mount is changed, and no tmpfs `/tmp` storage is used. The tests'
short-path assumptions are satisfied without changing production or test assertions.
Builds use the scoped `target/`, `CARGO_PROFILE_DEV_DEBUG=0`,
`CARGO_PROFILE_TEST_DEBUG=0` and `CARGO_INCREMENTAL=0` to conserve disk space.

```sh
export CARGO_TARGET_DIR="$HOME/.cache/agent-ws/rex-m31-insert-path/target"
export CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 CARGO_INCREMENTAL=0
unshare -Ur -m bash -c '
  mount --make-rprivate /
```

### Independent review and fixes

Cursor-pool Opus reviewed `e73ed5e` and approved after three changes, all made. It found
no way to put a newline, escape sequence, control or unquoted shell metacharacter into
the PTY (351 random hostile names round-tripped exactly through sh, bash and zsh, and

- **A slow listing held up the host.** The request was awaited inside the host's command
  loop for up to eight seconds, so keys to every pane, events and other requests on
  that host waited behind a slow mount. It is now sent detached. A loopback test in
  which the server leaves the listing unanswered while it serves a session refresh

  `~/.cache/agent-ws/insert-path-review-before.log`.
- **Invisible formatting characters were not refused**, although the README said
  control characters were. They were always inside single quotes, so not an injection,
  but a name with a right-to-left override could display as a different name. See
  Refused characters above; tests cover typed paths, returned names and the kept joiners.
- **The field showed a magnifying glass**, which DESIGN.md reserves for search fields.
  It now shows a folder glyph.

Also added from the review: tests that `client.perform` and a host-returned client action
cannot open the browser, and a native assertion that the newline-bearing name is never
listed. README now says the path is quoted for a POSIX shell and goes to whatever
program is in the foreground.

## Limits and deferred work

- Native acceptance is local Unix transport and Bash, not SSH/HTTPS, Wayland, other shells,
  Windows paths, IME or a screen reader. This remains POSIX-shell quoting, not a guarantee
  about interpreting text in an arbitrary foreground program or inside an existing quote.
- The private native run does not intercept client wire requests. Exact request restrictions
  are checked by the headless channels and loopback protocol tests instead.
- Native denied/not-directory/old-server/disconnect fault injection and a real >2000-entry
  truncated server directory were not exercised; synthetic UI responses and protocol
  errors/timeouts cover those policies. No claim that this closes all of M3.1 or all rows
  grouped under T76–T79/G01–G02.
- **Go to Directory**, execution of `cd`, recents and the shortcut badge remain deferred.
  There is no action stub, setting or execution mode for them. The browser data and
  listing core can be reused by a separately reviewed later slice.
