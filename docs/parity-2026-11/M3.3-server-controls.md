# M3.3 — running duration and confirmed Stop server (partial)

Implemented and checked on Linux, **2026-11-12 (PST)**. Native Unix-socket
acceptance passed. Native SSH, macOS, Windows and Wayland were **not** exercised.
No release work, new dependency, setting, lockfile or vendor change.

## Shipped behavior

Settings → Server keeps its cached, **last reported** facts. A Server controls
card near the top adds:

- **Running for** while connected and only when the reported start timestamp is
  usable. It uses Activity's `now`, whole `m`, `h`, `d` units. The shared
  `connection::activity::time::reported_elapsed` uses the existing RFC 3339 parser
  and bounds: up to 60 seconds ahead counts as now; further ahead or older than
  365 days has no duration. Missing/malformed times have none. No duration is
  shown while disconnected, even with a cached start time.
- A page-owned minute redraw, following Activity's poll/wake pattern. It exists
  only while Settings → Server itself is visible, not under the confirmation,
  on another page or after closing Settings. It sends no host command or read.
  Original start/build strings retain their reported offset; this is elapsed
  time using two machines' clocks, not a clock-skew estimate or live monitoring.
- **Stop server…**, a quiet danger-tinted button with a wrapped consequence
  sentence, only for connected `unix://` and `ssh://` hosts. Connected network
  endpoints instead say a server can be stopped only from its own machine or
  over SSH. Disconnected hosts have no button.

The existing confirmation names the captured host, says every program running
in its sessions ends, gives the **last reported** session count when available
(or says it was not reported), says other clients disconnect, and says Rex Rune
will not start it again. **Cancel** is the default, including Enter. Cancel and
Escape send nothing and restore Server settings; Commands opens the same
confirmation and cancellation closes it. The page's count is never inferred
from the client's own session inventory.

`host.stop_server` is unbound, appears as **Stop server…** in Commands → Host's
last/destructive group, has a Shortcuts title/category and effective-key hints,
and is both `Remote::Never` and `requires_person`. A `client.perform` request,
even with consent enabled, cannot open it; neither can a returned `client.action`.
The pinned remote allowed set is unchanged.

## Exactly what is sent

Opening the page or confirmation sends **nothing**. Confirming consumes the
confirmation and sends one epoch-scoped `HostCommand::StopServer` to its captured
active host. Host identity, configured endpoint and connection epoch are checked
again; a changed target is refused, never silently retargeted. The worker also
checks the epoch before sending exactly:

```json
{"method":"server.stop","payload":{}}
```

There is **no `if_idle`**, no preflight status read, session operation, automatic
retry or reconnect replay. Refusals retain the server's message through the
existing bounded display-text sanitizer (controls/bidi/invisible characters
removed). A transport loss or timeout says the stop could not be confirmed and
to check the host before trying again: it does not claim the server kept running.
403, `not_supported` and `conflict` are errors, not reasons to choose another mode.

Outcomes appear in the existing host notice and as **Last stop request** on the
Server page, so an open Settings modal cannot hide the result. This is the last
attempt's outcome, not a claim about the server's present state.

### After a successful reply

The worker explicitly closes the control connection, as the API requests, then
uses the existing disconnected/reconnect path. It does not run normal
`after_request` session/layout refreshes after Stop. Failed commands are never
replayed. Ordinary attachment and startup behavior elsewhere are unchanged.

- **`unix://`:** the host becomes disconnected and retries opening the same socket
  with the existing backoff (2, 4, then at most 8 seconds). No Rex executable is
  invoked, no server or session is created. If a person independently starts a
  server there later, ordinary attachment can succeed again.
- **`ssh://`:** the old tunnel is dropped; another attachment attempt resolves
  the remote socket and opens a new OpenSSH forward. Default-socket discovery
  uses `rex server status --autostart=false` and socket checks; an explicit socket
  remains that socket. Neither path starts Rex. A missing default server can
  expose the pre-existing **Start personal server…** action, but running it
  requires a separate preview and explicit confirmation. Stop grants no such
  consent and never opens or accepts that dialog. Explicit custom sockets do
  not qualify for that missing-default-server offer.
- **`https://`/other network endpoints:** no Stop control or enabled Commands row.
  They are not redirected through another transport to make Stop work.

SSH aftermath is established by code inspection and existing setup/connection
suite coverage, **not a new native SSH stop experiment**.

## Limits and deliberate choices

- No native SSH stop, macOS, Windows compile/run, Wayland, screen-reader, or
  real TCP/Tailscale admission-failure check here; the latter refusals are
  simulated. CI on the other platforms is still required. No new OS-specific
  code or dependencies were introduced.
- No new clock synchronization, polling, server start/restart, `if_idle` mode,
  Tailscale management, menu-bar item or live Settings sidebar status.
- The year's bound is deliberately identical to Activity's, even for a genuinely
  long-running server; uncertainty suppresses duration rather than guessing.
- A network host may report a local listener, but that is not permission to stop
  it over the current transport. Only the actual configured Unix/SSH path qualifies.
- An embedded local server cannot be identified reliably from these cached facts;
  its `not_supported` response is reported without retry.
- There was no need to expand the brief. The short units, early controls card,
  Cancel default, last-attempt page message and explicit SSH re-start consent
  are conservative choices within it. No decisions were awaited and no subagent
  was started.

README, AGENTS, DESIGN, the earlier M3.3 records and Unreleased Added were updated.
No versions, released changelog sections, lockfile or vendored sources changed.
The branch is `parity/server-controls`; nothing is pushed or released. Build
artifacts are removed with `cargo clean` only after checks and evidence are saved.
